# `ops/tickets_inbox/` —— 票据收件箱（并发施工协议，W-0）

## 为什么有这个目录

`ops/tickets.md` 是**一张全局编号的表**。多个代理同时在同一棵工作树上干活时，
两个人各自往表尾追一行 `N-133`，git 层面不冲突、语义层面**编号撞车** ——
而撞车的表现是「票据表看起来好好的」，直到有人引用 N-133 才发现指的是两件事。

所以：**没有人直接改 `ops/tickets.md`。** 要登记的事项写到本目录下自己那一份，
阶段收口代理统一编号并入主表。

## 怎么写

一张卡一个文件：`ops/tickets_inbox/<卡号>.md`（如 `W-0.md`、`s2-cor-01.md`）。
沿用 `tickets.md` 的表格格式，**编号一律先写 `N-?`**：

```markdown
| 编号 | 事项 | 状态 | 说明 |
|---|---|---|---|
| N-? | 一句话说清是什么 | 待处理 | 为什么、在哪、怎么复现、建议怎么办 |
```

- **编号由收口代理分配**，写在收件箱里的 `N-?` 不许自己填数字。
- 「说明」那一栏是给**不在场的人**读的：路径、命令、判据，缺一样就得再问一次。
- 只写**登记**，不写修法之外的争论；有裁定需求的，在说明里写「需裁定：A 还是 B，倾向 A，因为…」。

## 收口时怎么并

收口代理：读完本目录全部文件 → 按 `tickets.md` 的现有最大编号顺序分配 →
逐行并入主表 → **删掉已并入的收件箱文件**（留着会被并第二次）。
并入这一步和其它对 `ops/tickets.md` 的写一样，要在 `locks/git.lock` 的 flock 里做。
