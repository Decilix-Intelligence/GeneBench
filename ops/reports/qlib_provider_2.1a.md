## 2. 三个问题的落地

### Q2 `vwap` = `amount / volume`

**① 单位陷阱：实测，没按文档假设。** 湖 `daily` 的 `amount` 单位是**元**、`volume` 是**股**，
换算系数 **1** —— tushare 原生的千元/手已在 platform 流水线里归一过。

**② 判据用签字人给的那条**（`low <= vwap <= high` 的占比），并**配了负例对照**：

| 公式 | 落带率（相对容差 1e-6，全表 14,581,977 行） |
| --- | ---: |
| **`amount / volume`（我们采用）** | **99.984303%** |
| `10 × amount / volume`（tushare 文档口径） | 0.000137% |
| `amount / volume / 10` | 0.000110% |
| `amount / volume × 1000` | 0.000000% |

判据的判别力是 **7 万倍**，不是勉强过线。逐年最低 99.6%（2015 年），
中位 `vwap/close` 逐年都在 1.000 附近 —— **单位没有中途变过**。

**③ `volume = 0` 的行 `vwap` 记 NULL，不记 inf/0。**
**判别力披露**：实测全表 `volume <= 0` 的行 **0 条**，这条守门当前是**空转**的。
不假装它被测过 —— 验收改用**构造数据**直接打 `_adjust()`，证明守门代码本身有效
（`volume=0` → `NaN`，且断言「必须是 NaN 不能是 inf」）。

**131 条依赖 `vwap` 的因子按后端分（爆炸半径）**：
`qlib_expression` **69** · `qlib_panel_loader` **32** · `qlib_kunquant_loader` **30**。

### Q3 复权：后复权价 + `factor` 列，基准定死冻结线

```
L_c    = max{ t <= 2026-07-31 : adj_factor(c, t) 存在 }
factor = adj_factor(c, t) / adj_factor(c, L_c)

open/high/low/close/vwap = 原始价 × factor
volume                   = 原始股数 / factor
amount                   = 原始金额（不复权）
```

- **5,548 只**票在冻结线当天在市 → `factor(2026-07-31) = 1`，**存储价 == 原始价**。
- ⚠ **269 只**在冻结线前已退市/停更，「冻结线当天」对它们不存在 →
  以**自身最后一个有 `adj_factor` 的交易日**为基准。这是必要偏离，已写进数据卡；
  逐票基准落 `norm_base.parquet`，是产物的一部分，不是代码里的魔数。

**社区那份的归一化方式是实证反推的，不是猜的**（签字人要求的做法）。
拿 `sh600000` 逐日对拍 4,221 天：

| 关系 | 实测 | 结论 |
| --- | --- | --- |
| `close_社区 / factor_社区` ÷ 原始收盘价 | ∈ [0.99999986, 1.0000001]，中位 **1** | 社区遵守 `$close/$factor == 原始价` |
| `close_社区` 首日值 | **1.000000** | 社区按**每票首日 close = 1** 归一 |
| `amount_社区 / amount_湖` | **0.001**，全 4,221 天**只有 1 个取值** | 社区 `amount` 是**千元** |
| `volume_社区 × factor × 100 / volume_湖` | **1.0000** | 社区 `volume` 是**手**且已 `/factor` |
| `factor_社区 / adj_factor_湖` | 0.0391056 … 0.0391165（2,152 个不同取值） | 两边的因子**不是同一条曲线**，相对差 ~2.8e-4 |

最后一行是 §4 分歧的主因之一。

## 3. instruments 与日历

**instruments 取自 `universe_pit` canonical**，四个宇宙：

| 宇宙 | 区段行数 | 去重码数 | 其中 `ambiguous` |
| --- | ---: | ---: | ---: |
| `csi300` | 1,507 | 825 | 1 |
| `csi500` | 3,025 | 1,738 | 2 |
| `csi1000` | 4,455 | 2,839 | 1 |
| `all` | 5,813 | 5,813 | 0 |

**`ambiguous` 区段照常保留（4 条）**，provider 不做筛选。验收里配了判别力断言：
先断言 `universe_pit` 里真的有 `ambiguous` 行（否则这条是空的），再逐条断言它们在名单里。

**日历停在冻结线，且不出 `day_future.txt`。** 结构保证的硬证据是这一行：

```
qlib 读回：{'rows': 44, 'cols': ['$close','$factor','$vwap','$volume','$amount'],
            'last_factor': 1.0, 'csi300_n': 300, 'cal_max': '2026-07-31', 'cal_n': 139}
```

即**在 qlib 自己眼里**，2026 年只有 139 个交易日、上界就是冻结线 ——
红线 7 不再依赖每次调用的自觉。`csi300` 在冻结线当天恰好 **300** 只，
`factor` 在冻结线当天恰好 **1.0**。

**与卡 1.4 的规则差别（两处都对，理由不同）**：快照表 `trade_cal.parquet` **保留**
153 行未来日历（capture_time 语义，T+N 对齐要用）；provider 的 `day.txt` 截到冻结线
（它决定因子能在哪些日子求值）。`test_03b_no_future_calendar_and_snapshot_still_has_one`
同时盯住两边 —— 谁把其中一处「统一」掉，那条就红。

**bin 不走 `dump_bin.py` 的 CSV 往返，是直写的**（避开 float64→字符串→float32 的精度损失）。
格式不是猜的：从 `FileFeatureStorage.__getitem__` 的 `fp.seek(4*(i-start)+4)` 读出来，
并用社区 release 的 `sh600000` 逐值复现验证过。**格式对不对不由我们自证** ——
由 `D.features()` 判，那条测试是格式的唯一硬证据。

## 4. ⑤ 与社区 release 的收益率级比对（诊断，不作判据）

**为什么比收益率不比价格水平**：两边归一化常数不同（我们 `factor(冻结线)=1`，社区首日 `close=1`），
价格水平**必然**差一个比例；收益率是归一化不变量。

**为什么不作判据**：两源同宗（都出自 tushare），一致不构成互证 —— 与卡 1.1 的 B-07 同一条理由。

抽样 377 只 / 1,028,237 对收益率（种子 20260731）：

| 指标 | 值 |
| --- | ---: |
| 逐票收益率相关系数 中位 | **0.9999921** |
| 同上 P1 / 最小 | 0.999018 / 0.996528 |
| `abs(Δr) < 1e-3` 的对数占比 | **99.045%** |
| `abs(Δr) < 1e-4` 的对数占比 | 64.931% |
| `abs(Δr)` P50 / P99 / max | 5.61e-05 / 9.81e-04 / 0.1412 |

**分歧最大的三例摊开看，是谁错？**

| 票 · 日 | 我们 | 社区 | 湖的原始 `close/close` | 湖 `pct_chg` | 当日 `adj_factor` 变化 | `dividend` 除权记录 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| `300093.SZ` 07-03→07-06 | **-0.087608** | +0.036155 | **-0.087609** | **-8.7609%** | 无（2.0701 → 2.0701） | 无 |
| `603996.SH` 05-06→05-09 | **+0.028571** | +0.018519 | **+0.028571** | **+2.8571%** | 无（1.536 → 1.536） | 无 |
| `601005.SH` 08-08→08-09 | **+0.009346** | +0.017857 | **+0.009346** | **+0.9346%** | 无（1.051 → 1.051） | 无 |

**三例里我们的收益率逐位复现湖的 `close/close` 与 `pct_chg`，社区都不复现。**
这三天 `adj_factor` 没变、`dividend` 表当日无除权记录 —— **差异不可能来自复权口径**，
只能是社区的原始价与湖不同。后两例都是 0.35 / 1.07 这个量级的低价股，
社区的收益率恰好落在 `1/54`、`1/56` 这样的粗格点上，而我们是 `1/35`、`1/107`。

**诊断结论：没有在我们这一侧发现 bug。** 这条只作找 bug 用，不作正确性证明。

## 5. 已知缺陷（登记，不静默修补）

| # | 事实 | 影响 | 处置 |
| --- | --- | --- | --- |
| **N-20** | `vwap` 越出 `[low, high]` 的行 **2,291 条 / 14,581,977（0.0157%）**。主因是源侧 `amount` 被舍到**整数元**（2,233/2,289 条 `amount` 是整数），1,156 条在北交所，集中在 2016–2022 | 131 条依赖 `vwap` 的因子 | **不静默修补**。网关只发 `amount` 与 `volume`，agent 自己算 `vwap` 会得到**同一个数**；改了 gold 就与执行面不同源，差异会被误记到 agent 头上。计数与 15 条样例落 `ops/acceptance/card_2.1a_full_verify.json` |
| P-2 | 3 个码 `000022.SZ` / `000043.SZ` / `300114.SZ` **有价无名单**（代码变更注销，不在 `stock_basic`） | 有 features、不在任何 instruments | 保留 features（丢了 `code_alias` 的适配赛道就没数据），不塞进名单（会破坏第 ④ 条验收） |
| P-3 | 2 个码 `000805.SZ` / `000787.SZ` **有名单无价** | 在 `all.txt` 里、无 features | 保留在名单（逐区段相等是硬验收），qlib 读出来是 NaN |
| P-4 | bin 是 **float32** | 反算原始价有 ~1e-7 相对误差 | 验收用 1e-5 容差；实测最大 1.17e-07，余量 85 倍 |

**为什么 N-20 选「不修」而不是「clip 到 `[low,high]`」或「置 NULL」**：
决定性的论据不是「改动很小」，而是**执行面同源**。
gateway 暴露的是 `amount` 与 `volume`，不暴露 `vwap`；
agent 要用 `vwap` 只能自己 `amount/volume`。
我们若在 gold 里修，gold 与 agent 的输入就不是同一个函数了 ——
**标定口径与评测口径分叉**，正是我们选方案 C 要避免的那件事。
顺带，修了会破坏 `vwap × volume == amount` 这条免费的内部一致性检查。
