# 适配模块（GeneQuant 协议 v1 · 适配条文）

这个目录在容器里挂在 `/task/adaptation/`。**题面只说它「若存在」** —— 发现并使用它是你的事，
与 `/task/protocol/` 同一条摆放规则。

它解决的是一件很窄的事：**上游交来的产物不是按本协议的口径写的**。
你要把它修成合规产物，而不是重做一遍上游的工作。

## 三条规则（判据原文见 §3.3）

### 1. 源中缺失的信息保持缺失，不得由 agent 补全

> 「源中缺失的信息保持缺失、不得由 agent 补全」

上游没带的口径，你**不许**替它挑一个。正确做法是把该字段标成 `"unresolved"`
（声明类字段）或 `"unsupported"`（本协议不认这个概念时），并且**不要**产出依赖它的数
（依赖关系见 `/task/protocol/payload_depends_on.json`，没有这份文件时见目标 schema 的
`x-nullable-when` 注记）。

挑一个而不说，就是把一个不确定性藏进一个看起来很确定的数字里 —— 这一条与
`/task/protocol/` 的三态是同一条规则，只是这里的缺口来自**上游**而不是题面。

### 2. 翻译要声明

> 「agent 提出翻译、协议裁决可接纳性」

单位换算与字段/枚举/代码写法的翻译，**由你提出**：在产出里把翻译后的值写成本协议的口径。
可接纳性由协议裁决 —— 也就是说：

* 换算规则在 `unit_table.json` 里的，照它换；
* 别名在 `field_map.json` 里的，照它翻；
* **两张表里都没有的**，不是「你自己想一个」，而是**不可接纳**：按规则 1 标记，停在那个字段。

一个翻译只有在表里能查到、且查到的结果**唯一**时才成立。表里给出两个候选而源里没有更多信息
分辨 → 同样按规则 1 标记。

### 3. 有效产物进入它语义完整所支持的最早协议阶段

> 「有效 artifact 进入其语义完整所支持的最早协议阶段 —— 完整定义可进上游研究阶段、
> 信号可进组合构建、TargetPosition 可进回测或模拟交易」

修好的产物写到题面指定的产出路径（通常 `/task/artifact.json`），它的 `stage` 就是源产物自报的
那个阶段 —— **不要**因为修不动某个字段就把它降级到别的阶段，也不要把它抬到更下游。

## 你会看到什么

| 文件 | 是什么 |
| --- | --- |
| `adaptation.md` | 本文件 |
| `field_map.json` | 三家常见数据源（tushare / yfinance / akshare）与本协议 schema 的字段名、枚举值、代码写法对照 |
| `unit_table.json` | 单位对照：源侧单位 → 本协议单位的换算 |
| `MANIFEST.json` | 上面几件的封闭清单（每件带 sha256）|

## 输入侧

`/task/input/broken.json` 是上游交来的产物。
`/task/input/source_meta.json` 是它的交付说明：来自谁、哪些路径用的是源侧单位、
哪一项上游根本不带（`not_carried`）。**交付说明不含答案**，它只告诉你源的口径。

## 自检

修好之后照常跑 `/task/protocol/validate_artifact.py`（若该目录存在）。
它查结构，不查对错 —— 退出码 0 不代表翻译对了。

## 不在 v1 里的

* L4（跨协议版本迁移）与 L5（算子语义分叉的适配，见 `ops/specs/operator_semantics_conflicts.md`）
  **不在 v1**，记 v1.1。
* 本模块不做「猜」的兜底：没有兜底默认值，这是设计，不是缺件。
