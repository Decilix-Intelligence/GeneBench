# 卡 5.4：替换基线阶梯 —— 阶段分的锚定归一

**排期**：M5 全部完成之后、**M6 冒烟之前**。不阻塞 M3 / M4，
但 **M6 出主表之前必须完成**。

## 为什么需要这张卡

阶段分现在归一到 0–100，但**刻度是拍的** ——「S3 = 74」没有物理意义，
profile 图的 **y 轴因此没有定义**。这张卡用**可执行基线**实测出每个阶段的
**地板**与**上沿**，把刻度换成**锚定归一**。

## 阶梯定义

每阶段三档，**全部是可执行模块**，跑**同一套冻结上下游**与**同一评分器**。

| 阶段 | 地板 | 中间 | 上沿 |
| --- | --- | --- | --- |
| **S3 因子构建** | random/placebo 因子（用与真因子**相同的数据规模**生成随机值，**保证不是全常数**）| simple hand-crafted（动量 / 反转 / 波动率各一，3–5 条，**写死表达式**）| 因子库 existing-set 最优（从 792 条里按 **gold IC** 取 top-k）|
| **S4 因子验证** | no-filter（全量入选）| 固定 IC/RankIC 阈值 | t-stat + FDR selector |
| **S5 策略构建** | 随机信号 / 等权无区分 | best single factor + rank rule | LightGBM（**预注册参数，不调参**）|
| **S6 组合构建** | previous-holdings / no-trade | 1/N 等权 | Mean-Variance（**同一 risk/cost 输入**）|

**S4 的 Oracle（事后已知最优）只作 Selection Regret 的上界参考，
不进阶梯、不参与归一。**

### S1 / S2 / S7 / S8 本轮**不做**阶梯

它们的主指标是**正确性类**（Cov / PIT / Align / Adj / Fid / Cons / Audit 等），
**天然有 0 与 100 的语义**（全错 / 全对），不需要外部锚。

> **这个区别要写进文档**：**效果类指标需要锚定归一；正确性类指标本身就是有界的。**

## 归一公式

```
stage_score = 100 × (被测 − 地板) / (上沿 − 地板)      夹到 [0, 100]
```

地板与上沿在**同一窗口、同一 gold、同一评分器**下实测得到，
**写进快照 manifest 随版本冻结**。

**超过上沿的允许显示为 >100**，但主表夹到 100 **并标注** ——
被测系统真的超过 existing-set 最优是**一个值得看见的事实，不要静默抹掉**。

## 三条纪律

1. **基线模块与被测系统走完全相同的通路**：同一网关、同一 `as_of`、
   同一 artifact schema、同一探针。**基线若绕过网关直读数据，地板与上沿就不可比。**
2. **基线一律走 validity gate**：地板模块若触发探针
   （比如 placebo 因子恰好全常数触发 N-17），该次结果**同样记 `invalid`**，
   不能因为「它是基线」就豁免。
3. **每档基线的实测值连同其配置**（随机种子、参数、**代码 sha256**）**一并入 manifest**，
   任何人可复算。

## 判别力检查 —— 这张卡自身的验收

跑完之后**必须**成立三条，否则阶梯没有意义：

| # | 判据 | 不成立时 |
| --- | --- | --- |
| 1 | **地板 < 中间 < 上沿**（严格单调）| 说明某档定义错了，**停下汇报** |
| 2 | 地板与上沿的间距**显著大于 ε/τ 的容差带** | 否则整个刻度落在噪声里 |
| 3 | `oracle_agent` 的阶段分落在**上沿附近或以上**；`null_agent` 落在**地板附近或以下** | 这两个已有的 **agent 级**锚点与新的**模块级**锚点应当**互相印证**；若矛盾则其中一套定义有问题 |

## 与论文的关系
