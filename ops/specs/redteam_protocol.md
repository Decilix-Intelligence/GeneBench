# 红队流程：校验类卡的标配验收（2026-09-02 定稿）

**适用**：凡产出「判定器」的卡 —— 卡 2.3 schema 校验器（首例）、**卡 5.1 探针族、卡 5.2 L3 结算、卡 5.3 报告器**。
这三张卡**都要过一轮**，不过不许收口。

**为什么它是标配而不是加分项**：判定器的失败形态天然是 D-06 那个——合法样例全过、非法样例各自被拦，
所有可见信号都绿，而某条规则其实是空的。**作者自己写的负例证不了这一点**，因为负例与规则同源；
只有互不知情的攻击者拿着源码去找「能过校验但违反冻结项」的产物，才照得出来。
卡 2.3 的实测：作者写了 40 条非法样例、34 条 exclusive，红队仍确认了 36 条洞。

---

## 1. 流程（六视角 × 两轮 × 每条两个独立复核者，默认驳回）

| 步骤 | 内容 | 硬要求 |
| --- | --- | --- |
| 攻击 | 六个攻击者各持一个**视角**，拿到：规格、判定器源码、现有样例、合法起点、跑板 | 每条发现**必须实跑判定器**，把实际输出原样写进报告；只报有把握的；最多 8 条 |
| 三类 bug | **A** 静默通过（ok 但违反冻结项）/ **B** 判错级别或探针族 / **C** 误拒（合规却被拒）| C 类的危害不低于 A：它让合法运行 SR 记失败 |
| 复核 | 每条发现两个**独立**复核者：**复现视角**（亲自重跑、核 bug_class、核规格确实承诺过）+ **范围视角**（是不是判定器层的事、是不是攻击者自造的要求、与已有样例是否重复）| **不确定默认驳回**；两票都 isReal 才确认 |
| 第二轮 | 攻击者拿到第一轮已确认清单（不重复报，可报同一规则的不同绕过）| 两轮后停；若第一轮零发现也停 |
| 入库 | 确认项的 case **原样**入库当回归夹具，逐条写明修后期望（A/B 类要被指定 code 拦下，C 类必须通过）| **不重写攻击者的 case**：重写会把作者的理解再一次带进去 |
| 归并 | 确认项按根因归并，写进该卡规格的「红队结果」节 | 根因数通常远小于发现数（卡 2.3：36 → 12）|

**视角的选法**：按判定器的**输入面**切，不按代码结构切。卡 2.3 用的六个：三态语义与任务上下文 / 值语义（S5 的 null-flat）/
交叉核（日志读取集）/ 数值与守恒 / 版本-信封-scorer / **误拒**。误拒视角必须有 —— 其余五个都在找「放过」，只有它在找「错杀」。

**跑板**：给攻击者一个一行命令的跑板（`python3 redteam_run.py case.json → {ok, codes, gate_failed}`），
否则他们会各自发明调用方式，报告不可比。

## 2. 两个根因，单独成节 —— 判定器「验申报不验行为」的两种具体形态

写探针时**对照检查**这两条。它们不是卡 2.3 的偶然 bug，是判定器这类代码的固有诱惑。

### 2.1 以自报值为切片键 / 为基准

| 形态 | 卡 2.3 的实例 | 后果 |
| --- | --- | --- |
| **切片键来自被判者** | 网关日志按 artifact **自报**的 `task_id` 切片 | 改一个字母，S1/S3/S8 的所有交叉核整体关掉，且**无任何信号** |
| **基准来自被判者** | S2 静默补行、S3 读取集、S5 rank 语义的判定读 artifact **自报**的口径 | 改一句口径，整族探针不响，只剩 `declaration_mismatch`（另一族）|

**规则**：交叉核的**每一个输入**都要问「这是谁给的」。切片键与基准必须来自**任务侧**（TaskSpec）或**基础设施侧**
（网关日志、可交易性视图）；被判者自报的东西**只能是被核的对象，不能是核的依据**。
卡 2.3 的落地：`_task_context_sane()` 核 `artifact.task_id == task.task_id`；`_effective()` 任务已声明取任务值。

**检查清单**（写探针时逐条过）：
- [ ] 日志/视图切片用的键，来自任务侧还是 artifact？
- [ ] 判定「声明了 X」时，读的是任务声明还是 artifact 自报？
- [ ] 若 artifact 与任务不符，是否**同时**报 `declaration_mismatch` **和**原探针族？（两族独立计）

### 2.2 Python 相等 ≠ JSON 相等

| 形态 | 卡 2.3 的实例 | 后果 |
| --- | --- | --- |
| bool 是 int 的子类 | `[true, 5, 20]` 通过「⊆ {1,5,20}」；`true == 1` 让 `declaration_mismatch` 不响 | 类型混同在比较里消失 |
| 标量门放过容器 | `{"value": "post"}` / `["fill_zero"]` 跳过枚举与违例表 | 结构不合法被判成「值不同」甚至通过 |
| 大整数与 `isfinite` | `math.isfinite(10**400)` 抛 OverflowError | 判定器自己异常 —— 也是一种静默失败 |

**规则**：判定器面对的是 JSON，比较必须是 **JSON 语义**的：先比 JSON 类型（bool 单列）再比值；
枚举字段先做结构检查（必须是字符串且在枚举内），**结构不合法先落 malformed，再谈值对不对**；
计数用非负整数判型，数值判型对 bool 显式排除。卡 2.3 的落地：`_json_equal()`、`_num()`、`_count()`、`DECLARATION_SHAPES`。

**检查清单**：
- [ ] 任何 `==` 比较的两侧，JSON 类型一致吗？
- [ ] 枚举/形态检查是否在值比较**之前**？
- [ ] 判定器在任意 JSON 输入上都不会抛异常？（`validator_exception` 出现在任何样例上都是 bug）

## 3. 驳回后按三态纪律捞回的三条（记明理由）

复核者以「规格未承诺」驳回、但我仍采纳的三条 —— 理由不是「以防万一」，是它们与已签字的**三态纪律**同形：

| 发现 | 复核驳回理由 | 捞回理由 |
| --- | --- | --- |
| scorer `invalid` 时 `effect` 键**缺失**（而非 `null`）被接受 | 规格只写了「必须为 null」 | **缺失 ≠ 标记**是三态的核心；`{}`/`0` 已判畸形，缺失若放过，就是三态在 scorer 侧没落实 |
| S5 同一 `(date, symbol)` 重复两行、一行 null 一行有值 | 规格未禁重复 | 重复格让 `null` vs 值的判定**取决于读到哪一行**——静默的不确定性 |
| `provenance` 引用自己 | 规格未禁 | 引用链成环 → Audit「事件链可重放」结构上不成立 |

**未捞回的一条要交代**：「suspend 格子写 0.0 不触发 fillna 探针」（S2 把 suspend 算缺行，S5 只认 `no_data`）。
两阶段口径不一致是真的，但 suspend 日有没有观点在语义上确实可以两说 —— 留给卡 3.2 出题时统一，不在校验器里拍。

## 3b. 「未判」是独立状态，默认不算通过（2026-09-03）

卡 2.3 那轮有 7 名复核者撞额度中断，产出被混进「驳回」堆里 —— 已分开。规矩固化：

| 状态 | 含义 | 处置 |
| --- | --- | --- |
| `confirmed` | 复核者独立取证后认账 | 修 |
| `refuted` | 复核者独立取证后驳回，理由入案 | 不修，理由留档 |
| **`unadjudicated`（未判）** | 复核者未产出结论（撞额度、超时、崩溃）| **默认不算通过**：要么补跑，要么在验收里显式记「本条未经独立复核」|

把「未判」并进「驳回」会让漏判看起来像是被审过 —— 这正是红队想防的那类假信号。

## 5. 审查强度分层（2026-09-03 签字）：探针题全量对抗，规定题抽样

八轮对抗复审都是在 40 题上全量跑的，成本已经压过收益。**分层，按「这道题的读数对措辞有多敏感」切**：

| 题型 | 数量 | 验收强度 |
| --- | --- | --- |
| **探针题**（`underdetermined_probe`）| **8 道**（每阶段 1 道）| 机械规则全过（E1–E13 / C1）+ **对抗复审** + **签字人逐题人工签字** |
| **规定题**（`regulated` / `free`）| **32 道** | 机械规则全过（E1–E13 / C1）+ **每阶段抽 1 道**贴签字人过目；其余**按规则放行** |

**理由 —— 规定题没有「欠定字段」这个最敏感的读数**。探针题的主读数是一个二值行为：面对少了一项的声明集，
agent 是标 `unresolved`，还是静默挑一个值。臂间任何一点措辞差异都直接改这个概率 —— 显著性（E11 / E12b）、
可扫描性（E10 / E12）、指针词（E5）、强度差（「不得」vs「不要」）：第七、八轮判红的每一条都是这个形态。
规定题的读数是**产出与 gold 比数**，措辞差异要先改变 agent 的计算过程、再穿过 ε 带才看得见，**后果小一个量级**；
而且规定题把正确行为在题面里写全了，没有「题面没说的那一项」留给措辞去暗示。

**八轮对探针题是值得的，不是走过场**：每一轮都抓到会改变 agent 行为的东西 ——
7b 五处实质不对称（当时 E1–E4 全过）· 7c 15 处 → 5 个根因 · 第六轮 E7 漏掉结算方式与科目 id ·
第七轮 E10b（正文键名与键路径，判红 26 + 30 处）与 S8 六处 · 第八轮 E11 升级为「独立成**段**」+ E12b ·
第九轮 E13（两臂**一起**要求 agent 藏证据）。**零发现的那一轮还没出现过** —— 出现了才是停的信号（§1 的停止条件）。

**规定题怎么抽**：每阶段 1 道，优先抽该阶段模板最新改动过的那道。抽中的那道**若判红，该阶段其余四道全部退回全量复审** ——
抽样是对「规则已经收敛」下的赌，赌输就退回，不是永久豁免。放行的那些**照样过机械规则全套**，
分层砍掉的只是人工与对抗那两层。

## 6. 沙箱化 B 补丁法：拿独立实现当判据的标准流程（2026-09-03 固化）

**适用**：凡要**在独立实现上做隔离实验**的场合 —— materiality screen（卡 3.2 §3b 的 E9d2 证据）是首例，
将来卡 5.2 的 L3 结算、任何「换一个口径看指标动不动」的取证都走这一套。

**为什么它属于红队协议而不是某张卡的实现细节**：这类实验的失败形态**又是 D-06 那个** ——
跑出了一堆数、报告全绿，而那些数其实是**我们自己的 harness 造出来的**，不是实现之间的真实分歧。
差别在于这里被判的不是判定器，是**取证过程本身**；两道门就是给取证过程配的负例。

### 6.1 四步（顺序不能改）

| 步 | 做法 | 为什么不能省 |
| --- | --- | --- |
| **① 复制到沙箱** | 把实现源文件复制到 `/tmp/gb_screen/<run_id>/{gate0,main}/B<i>/`，输入数据用 **symlink**。**快照目录一个字节都不改**，跑完 `git status --porcelain` 必须为空 | 独立实现是**证据**。在原地改它，证据链就断了 —— 而且下一次谁也说不清读到的是原件还是改过的 |
| **② 带断言的精确开关补丁** | 补丁按**锚点字符串**定位（`grep -n` 出来的那一行原文），命中数不为 1 就**中止**，不产出。**不用模糊 diff、不用行号** | 行号会漂，模糊 diff 会「差不多匹配上」然后改错地方 —— 而改错地方的产物**看起来完全正常**。断言是这一步唯一的报警器 |
| **③ 子进程跑** | 走各实现自己的 CLI `main`，**不 `import` 它们的 `run()`** | 三份 B 的 `run` 签名互不相同，按 `run` 接线要给每份猜内部数据结构 —— 那就是「伪造 runner」的滑坡。CLI 是快照里那批产物的**原生成路径**，走它才有 Gate 0 可比 |
| **④ 读它自写的 JSON** | 读实现自己写出的 `out_v2_b<i>_<freq>.json`，**不在 harness 里重算任何指标** | harness 一旦参与算指标，「实现之间的差」就掺进了「我们算法的差」，而两者在结果里不可分离 |

**补丁契约（四条，与 ①–④ 同等强制）**：
1. **只加开关，不改算法**。允许的编辑形态只有一种：把一个**已经存在的**合取项 / 赋值语句，包进一个由环境变量驱动的分支。
   禁止改排序键、`n_drop` 上限、可交易性过滤、预算分配、日历的其余分支。
2. **开关默认值 = 该实现打补丁前的原读法，不许对齐**。三份的原读法**本来就不一致** ——
   `first_rebalance_day` 上 b1/b2 默认 `window_start`（`impl_v2_b1.py:153` 的 `keep[0] = True` /
   `impl_v2_b2.py:147` 的 `mask[0] = True`），而 `impl_v2_b3.py:126` 的 `rebalance_days` **根本没有首日强制**。
   为了让三份「跑出一样的结果」去对齐默认值，就是把独立性亲手抹掉。
3. **补丁入档**：文本补丁进版本库（`ops/screen_patches/<patch_id>.<impl>.patch`），报告逐题记
   `patch_id` / `patch_sha256` / `src_sha256` / `patched_sha256` / `env` / 锚点原文。
4. **三份补丁互不参考**：环境变量名是**协议**（可以一样），分支写法各按各自的数据结构写。

### 6.2 双门：Gate 0 与 Gate 1

**两道门防的是两件不同的事，缺一道另一道补不上。**

| 门 | 跑什么 | 判据 | 它防什么 |
| --- | --- | --- | --- |
| **Gate 0（复现门）** | **未打补丁**的沙箱副本，按原样跑一遍，与**快照里的既有产物**逐指标比 | 最大相对差 **< 1e-12**；**实测偏差逐项写进 `MANIFEST.json`**，不许只记「过了」 | **防 harness 自己改了行为**。沙箱路径、symlink、环境变量、Python/BLAS 版本、工作目录 —— 任何一处让实现跑出了别的数，后面所有的「分歧」都是我们造的。**没有这道门，screen 测的是自己** |
| **Gate 1（中性门）** | **打了补丁**的副本，开关取**各自的原读法**，与 **Gate 0 的产物**比 | **逐位相同**（不是「在带内」）| **防补丁污染实现独立性**。补丁若顺手改了别的东西（缩进吃掉一个分支、把某个 `&` 写成 `|`、把默认值对齐了），产物就不再是那份实现的产物 —— 而这种污染**在最终结果里长得跟真分歧一模一样** |

**为什么 Gate 0 的判据是 1e-12 而不是「逐字节相同」**：实测就不是逐字节可复现的。
2026-09-03 的基线跑 —— B1 最大相对差 **0.0**、B2 **3.48e-15**、B3 **1.54e-14**（两者的最差指标都是 `sharpe_net`），
来源是 **BLAS 的归约序**，与实现无关。要求逐字节会让这道门天天红，然后被人关掉 —— **一道会被关掉的门等于没有门**。
1e-12 比实测的噪声高约两个数量级，比任何真实的口径分歧（S7 `sell_rule` 是 1e-3 量级）低九个数量级。

**为什么 Gate 1 反而要求逐位相同**：它比的是**同一台机器、同一次会话里**的两次跑，
差别只有「文件里多了一个不该生效的分支」。这里没有 BLAS 噪声的容身之处 ——
**只要有一位不同，就说明补丁改了行为**，回滚重写，不许调判据。

**顺序**：Gate 0 → Gate 1 → 才跑真正出数的那次。**两道门都不产结论**，它们只证明 harness 与补丁没改行为。
门没过就停下汇报，**不许**降级成「差得不多，先跑着看」。

### 6.3 首例实测（2026-09-03，S7）

* **Gate 0 过**：最大相对差 1.5e-14（B3 `sharpe_net`）；偏差已入 `ops/reports/materiality_gate0_baseline.json` 的 `repro` 段。
* **Gate 1 过**：三份 B 打了 `P-SELL` 补丁、开关取各自原读法（`dropped_from_target`），
  产物 sha256 与 Gate 0 **逐条相同**（`3df0fb86…` / `3acf8cdd…` / `a9801a7e…`）。
* **结论**：`sell_rule` = material（B1 5 项 / B2 6 项 / B3 6 项超 daily ε 带）；
  `first_rebalance_day` @ daily = immaterial（9/9 逐位相同）—— **同一套 harness 判得出 immaterial**，
  这是这套流程的**判别力自检**，没有它「全是 material」与「橡皮图章」不可区分。
* **副产物 N-38**：正是补丁契约第 2 条（不许对齐默认值）逼出来的发现 ——
  三份 B 对「首日是否强制建仓」的默认读法不一致，日频下三份掩码全 True 故不可见，**周频/月频才显现**。
  若当初为了「让三份对齐」改了默认值，这条永远不会被发现。

**一条纪律 —— 两类数不得混用**：`A↔B 的整体差`（不同实现之间）与`同一实现内换取值的差`（本流程产出）
**是两个量**。前者混着所有口径差，后者才是某一个字段的隔离效应。
S7 的教训（**N-39**）：22.69% 是 A↔B 的整体差，被当成 A-1 的证据写进了结论，
而隔离实验实测只有 **0.38%–0.45%**，**相差约 50 倍** —— 排除法不是隔离实验。
`DIVERGENCE_EVIDENCE` 里登记的必须是本流程产出的隔离差，并**注明是哪一类数**。

### 6.4 与 §5「审查强度分层」的接口

## 7. 突变必须落在**门保护的对象**上，不能落在门的参数上（裁定 2026-09-04）

**这条是从一次实测里长出来的**，不是推演。卡 4.3 的冻结门有两条判别力测试：
一条把突变加在**期望常量**上（`expect_frozen_root="0"*64`），一条加在**通行证 dict**
上（`frozen_manifest={}`）。两条都绿得很好看，而门本身是空的 ——
改一个模板、题面真的变了，通行证 root 一个字都没变，`inject` 照常放行，
`pytest ops/test_inject.py` **35 passed**。

**为什么会这样**：那两条测的是「两个字符串不相等时会不会报错」，
而门要抓的性质是「**工作树里的模板变了，这个数会不会跟着变**」。
突变落在门的参数上，测的就只是参数传递；落在被保护的对象上，测的才是门。

**做法（每一道门都要回答）**：
1. 这道门**保护的对象**是什么？（模板字节 / provider 树 / bundle 文件集 / 迁移合法性 / 现金账）
2. 对**那个对象**做一次最小突变，门红吗？
3. 突变本身**真的改变了字节**吗？（`assert_mutated` 的老教训 —— 突变空转让判别力测试恒绿）

**已按这条逐门自查过的**：卡 4.3 十道门（P2/P4/P6a/P8/冻结/G4/L-5a 落点/L-5a 规范路径/L-5b/L-5c）
与卡 4.4 十二处（记账五处、迁移、Slip 两处、幂等、可交易性、T+1、投影）——
**突变落点全部改到被保护对象上**，10/10 与 12/12 全杀。
新写门时先写第 1 问的答案，再写测试。

**这是「门有了、门后没人」的姊妹形态**：那个是门本身缺实现（P4b 拦占位 digest 而无人钉 digest、
P8 只查顶层项、冻结门做成可选参数），这个是门有实现而测试没测它。
两个加起来在 4.3/4.4 这一轮各出现了三次和一次 —— 不是偶发。

## 8. 规格预言了一个失败形态 ≠ 实现免疫（实证纪律，2026-09-04）

卡 4.3 §6.5 的 ID-1 白纸黑字写着：

> keep-alive / 流水线连接上**每一个请求**都要重新剥注，「按连接盖一次章」不够

**这条规格是我自己写的。然后我把实现写成了「按连接盖一次章」** ——
剥注第一个请求，之后交给双向 splice，后续字节原样搬。
本地 510 个测试全绿；`ops/test_identity_injection.py` 的 10 条也全绿
（它们测的是 `rewrite_identity()` 这个**纯函数**，而纯函数是对的）。

**只有 T15 在 f02 真容器 + 真网关上抓到了**：同一连接连发两个请求，
网关日志第一条是 runner 真值、第二条是 `s9-forged-99` / `cfg-forged` / `strict`。

同一次还抓到第二个：边车代码挂的是 run dir **之外**的固定路径，
与代码库漂开时**身份注入静默失效** —— 容器照跑、日志照写，只是记的是伪造值。

### 因此

**四条容器测试（T5 / T10 / T12 / T15）必须在 f02 真跑** ——
这条从「签字人的裁定」升级为**有实证的纪律**：
上面两个缺陷，一个是规格已经点名的形态，一个是纯函数测试覆盖不到的接线，
**两个都只有真跑才暴露**。

### 一般化

写下「这里容易错」不产生任何防护。防护来自：
1. 一条**会红**的测试，且
2. 它跑在**真实的那一层**上。

纯函数测得再密，测不到「这个函数有没有被每个请求调用一次」。
凡是规格里出现「每一个 X 都要 Y」这种量词，就去问：
**测试是在一个 X 上测的，还是在多个 X 上测的？**
