# 量化研究员清单 × GeneBench 对接决定 v1

输入：《GeneQuant Benchmark 对接思路 v0.2》（专业量化研究员，2026-08-31，B1/B2/B3 三层 + 约 95 个科目 + 统一口径 + R1–R16 文献表）。本文件记录逐项采纳决定，与《GeneBench 指标规格 v1》配套使用：凡本文件与规格 v1 冲突处，以本文件为准；规格 v1 的 §1/§3/§5 按本文件 §2/§3 增补。

## 0 总判断

三层划分与我们的结构同构：B1 Agent 能力 ≈ Table A；B2 接入与语义保持 ≈ 适配赛道（v2）；B3 各阶段效果 ≈ Table B。因此对接不是重构，是在既有骨架上补三处结构性升级、补一批口径细节、补一份任务蓝图。

需要翻译的一处：**B3 的被测单元是"量化模块"，我们的被测单元是"agent 系统配置"**。研究员的反事实是"换掉 module，看 uplift"；我们的反事实是"换掉 agent 配置或换掉协议臂，看阶段分"。两者的骨架（冻结上下游 + 只替换一处 + 归因只归当次替换）完全一致，所以他的 frozen downstream harness 表可以直接当我们阶段隔离的实现细则用，但"baseline module"在我们这里的角色要改：不是竞争对手，是**给阶段分做锚点的刻度尺**（见 §1.2）。

独立收敛值得记一笔：他的 `B3-X-ECO-01`（仅更换成本/撮合引擎时上游目标持仓不应改变）就是我们的署名指标 Cross-Backend Consistency，一位不知情的专业研究员独立提出了同一条，这条在论文里可以作为设计合理性的旁证。

## 1 采纳：三处结构性升级

### 1.1 有效性闸门与效果分数分离（立即生效，改变 v1 的计分语义）

原话："PIT、no-forward-read、alignment、accounting、constraint legality 或 evidence binding 任一 blocking gate 失败，当次 performance result 标记 `invalid`，不进入 module ranking。"

我们此前把五探针当作 Table A/B 里的扣分列。改为**闸门语义**：探针失败的那次运行，其阶段效果分记 `invalid` 而非低分，不参与该阶段的效果排名与均值；同时在报告里单列 `invalid` 率。理由是扣分制存在一个致命漏洞——带前视的因子 IC 会显著更高，扣掉几分之后总分仍可能高于诚实实现，等于奖励作弊。闸门制堵死这条路。

对论文的正面影响：主实验一的三范式画像里，裸臂配置的低分将由两部分构成（能力不足导致的低分 + 违例导致的 invalid），这个分解本身就是一张有说服力的附图，也让"静默脑补率"从一个孤立指标升级成计分制度的一部分。

实现要求：scorer 输出每次运行的 `validity: {valid|invalid}` 与 `gate_failed: [探针 ID]`；阶段效果分在 `invalid` 时不产出数值。Correctness 类指标（Fid/Exec/Align 等）不受闸门影响，照常记录——它们回答"做对了没有"，与"结果可不可信"是两个问题。

### 1.2 替换基线阶梯：给阶段分锚点（修掉我们一个真实缺陷）

我们原先的阶段分归一到 0–100，刻度是拍出来的。研究员的 replacement baseline 提供了刻度的物理意义：每个阶段配一组可执行的基线模块，跑同一套冻结上下游，得到该阶段的**地板与天花板**。

v1 采用的阶梯（按可实现性收敛，非全量）：

| 阶段 | 地板锚 | 中间锚 | 上沿锚 |
|---|---|---|---|
| S3 因子构建 | random / placebo 因子 | simple hand-crafted 因子 | 因子库 existing-set 最优 |
| S4 因子验证 | no-filter（全量入选） | 固定 IC/RankIC 阈值 | t-stat + FDR selector（Oracle 只作 Selection Regret 上界，不进排名） |
| S5 策略构建 | 等权 / 随机信号 | best single factor + rank rule | LightGBM（预注册参数，budget-matched） |
| S6 组合构建 | previous-holdings / no-trade | 1/N 等权 | Mean-Variance（同一 risk/cost 输入） |

阶段分定义随之改写为**锚定归一**：`stage_score = 100 × (被测 − 地板) / (上沿 − 地板)`，夹到 [0,100]，地板与上沿由基线阶梯在同一窗口实测得到，写进快照 manifest 随版本冻结。这样"S3 = 74"读作"落在 placebo 与 existing-set 之间偏上"，而不是一个无来源的数。profile 图的 y 轴也因此有了定义。

基线阶梯同时给了论文一条现成的批评防线：任何"复杂系统未超过简单基线"的情形都会被这把尺子直接量出来，而不是藏在总分里。

### 1.3 搜索次数感知的紧缩：把多重检验用到 agent 自己身上（新增署名指标）

研究员 §4.4："若 factor/strategy/parameter trials 数量大于 1，必须记录 search count 与 family，报告 FDR / Deflated Sharpe / PBO。"

这条在我们的场景里有一个他不需要考虑、而我们独有的转折：**试了多少次这件事，只有 benchmark 知道，被测 agent 无法隐瞒**。agent 在轨迹里尝试了多少个因子候选、调了多少轮参数，全部落在网关访问日志与工具调用记录里。于是我们可以计算一个 agent 无法规避的紧缩分数：

- `SearchCount`：该次运行中产生并求值过的候选 artifact 数（网关取数模式 + 提交尝试双路计数）。
- `DSR@search`：以实测 SearchCount 为试验数的 Deflated Sharpe（Bailey–López de Prado），用于 S5/S6/S7 的效果结算。
- `IC_deflated`：以 SearchCount 为试验族规模的 FDR 校正后 IC 显著性，用于 S3/S4。

意义：暴力枚举一千个因子挑最优的配置会被自动紧缩，而三次尝试就命中的配置不会。这把"研究质量"与"算力堆砌"分开，也是目前 agent benchmark 里没有人做的事——通用 agent 评测不需要多重检验，量化研究离开它就不成立。这条建议进论文正文的指标贡献，且与我们的成本轴形成互补（成本轴量花了多少，紧缩轴量花得值不值）。

实现要求：runner 遥测新增 `search_count` 与 `trial_family` 字段（M4 卡 4.1 落实，但字段名现在就定，避免 M2/M3 产物没有位置承载）。

## 2 指标口径冻结增补（并入规格 v1 §3，M2 卡 2.2/2.3 必须现在落实）

| 项 | 研究员口径 | v1 决定 |
|---|---|---|
| IC 汇总 | 逐截面算再对时序汇总；报 mean/std/**positive ratio/coverage/CI** | 采纳。我们原只报 mean/std/ICIR，补 positive ratio、coverage 与 block-bootstrap CI |
| ICIR 年化 | 年化因子与频率必须冻结 | 采纳，写死 √252 日频、不年化时显式标注 |
| 分位/Spread | quantile 数、tie handling、equal/cap weighting、rebalance 时点、holding horizon 全冻结；报单调性与 Top-Bottom gross/net | 采纳，v1 定 10 分位、平均法处理平局、等权、收盘后调仓、持有期 {1,5,20} 日 |
| Sharpe 推断 | Lo (2002) 序列相关校正推断，gross/net 分开 | 采纳，新增。原规格只有 DSR/PBO，缺 Lo 校正 |
| Sortino | MAR 事先冻结，仅在下行观测上算下行差 | 采纳，MAR = 0 |
| MDD/Calmar | 由完整 NAV 曲线算；Calmar 的 return 窗口与 MDD 窗口一致；附回撤久期与恢复时间 | 采纳，回撤久期与恢复时间入扩展列 |
| Turnover/Cost | one-way 与 two-way 明确区分；佣金/税/价差/滑点/冲击分解；报 **cost break-even** | 采纳，break-even 升为 S5/S6 主指标候选 |
| Capacity | ADV 参与率、流动性桶、冲击曲线、资金梯度；报 net alpha 随规模衰减 | v1 只做资金梯度的简化版（三档资金），冲击曲线推迟 v2 |
| 尾部风险 | VaR/CVaR/最差日周月/压力期并列，不用 Sharpe 代替 | 采纳进 S7 扩展列 |
| 不确定性 | IC/spread/alpha/Sharpe 一律报 block-bootstrap 或 HAC/Newey–West | 采纳，替换原规格"只对 IC t 值做 NW"的窄口径 |
| 分层报告 | full OOS + 子周期 + 牛熊震荡 + 高低波动 + 大小盘 + 行业 + 流动性桶 + 市场迁移 | 部分采纳：v1 做 FinTSB 四模式 + 大小盘 + 流动性桶三层，行业与市场迁移推迟 |
| 事后挑选 | 事后选定的窗口/宇宙/成本/基准/指标只能作 exploratory，不进 confirmatory 榜 | 采纳，写进发布协议 |

另有两条 schema 级的语义冻结，必须在 M2 卡 2.3 的 artifact schema 里落位，否则后面补要改全部任务：

- **SignalArtifact 必须区分序数与数值**（S5-COR-01）：`value_semantics ∈ {rank, score}` 为必填字段，rank 语义下评分器禁止按数值距离加权。
- **缺失与主动空仓必须可区分**（S5-ROB-01）：`NaN`（无观点/数据缺失）与 `0`（明确空仓）是两个状态，schema 分别用 `null` 与显式 `flat` 表达，`fillna(0)` 在校验器里判违例。

## 3 探针族增补（并入规格 v1 §1，原五探针扩为五族）

原五探针（前视、日历、复权指纹、PIT 宇宙、欠定语义）保留为族首，各族按研究员清单补具体项。v1 落实以下十条，全部 L1 硬判、零裁判方差：

| 探针 | 来源科目 | 判据 |
|---|---|---|
| 抓取时点以引擎时钟为准 | S1-COR-03 | 产物申报的获取时间必须等于网关日志时间，不采信外部时间戳 |
| 数据源状态可分辨 | S1-ROB-02 | 网关对空结果/拒绝/限流返回不同状态码，产物须正确区分三者而非一律当空 |
| 回看窗口边界空值 | S3-COR-03 | 窗口未满期间必须为空；提前产出非空即违例 |
| 非有限值安全传播 | S3-ROB-02 | Inf/NaN 不得被静默替换为 0 或前值 |
| 因子退化检测 | S3-ECO-01 | 常数输出、有效覆盖率低于阈值必须报警而非静默通过 |
| 不支持算子显式拒绝 | S3-ROB-03 | 找不到算子时不得用近似算子替代（与协议 §3.1 同源） |
| 输入消融敏感度 | S5-ROB-02 | 抽掉核心输入因子后信号必须显著变化；不变即证明模块未真正使用输入 |
| 优化失败显式报错 | S6-ROB-02 | 求解不收敛时不得静默沿用上期持仓 |
| 复式记账守恒 | S7-COR-01 | 资金 + 持仓市值 = 净值，逐日守恒，残差超容差即违例 |
| 归因守恒 | S7-ECO-01 | alpha + beta + cost = total，残差入报告 |

其中"输入消融敏感度"和"因子退化检测"是这份清单给我们的两个最有价值的新探针：它们拦的是**看起来合法、实则空转**的产物，而这正是 agent 最容易产出的失败形态，我们此前的探针族完全没有覆盖。

## 4 v1 科目选择（研究员建议"挑着跑"，以下是选法）

原则：v1 的任务以**规定动作**为主干（判定硬、无裁判方差、直接支撑主实验一的阶段画像），每个阶段补少量**自由发挥**任务承载效果指标与基线阶梯。四类科目（COR 正确性 / ROB 稳健性 / ECO 效果 / OPS 工程）在每个阶段都要有覆盖，这是任务集的蓝图，也直接回答了 M3 卡 3.2"每阶段的题从哪来"。

| 阶段 | v1 选入科目 | 题型配比（每阶段 25 题） |
|---|---|---|
| S1 | COR-01/02/03、ROB-02/03、ECO-01、OPS-01 | 规定动作 22 + 自由 3 |
| S2 | COR-01/02/03、ROB-01/02/03、ECO-01、OPS-01/02 | 规定动作 25 |
| S3 | COR-01/02/03、ROB-01/02/03、ECO-01/02/03、OPS-01 | 规定动作 18 + 自由 7（配基线阶梯） |
| S4 | COR-01/02、ROB-01/02、ECO-01/02/03、OPS-01 | 规定动作 19 + 自由 6 |
| S5 | COR-01/02/03、ROB-01/02/03、ECO-01/03/04 | 规定动作 19 + 自由 6（配基线阶梯） |
| S6 | COR-01/02/03、ROB-01/02/03、ECO-01/02 | 规定动作 22 + 自由 3 |
| S7 | COR-01/02/03、ROB-01/02/03、ECO-01/02、OPS-01 | 规定动作 25 |
| S8 | COR-01/02/03、ROB-01（幂等）、ECO-01、OPS-01 | 规定动作 25 |

自由发挥题共 25 道，集中在 S3–S5，是 v1 里唯一需要基线阶梯与 OOS 窗口的部分，也是效果指标（IC/Spread/alpha/Sharpe 与 §1.3 的紧缩分数）的唯一来源。它们的存在保证 benchmark 不是纯粹的"实现正确性考试"——没有这 25 道题，我们无法就量化研究质量说任何话。

## 5 推迟与不采纳

推迟到 v2：S8 的幂等性以外的有状态项（乱序/延迟/重复事件、崩溃重启恢复）需要真正的事件驱动执行环境；容量与冲击曲线需要标定过的冲击模型；跨市场迁移需要第二个市场的数据；B3-X 跨阶段科目整体归 Chain 赛道；S5 的 budget-matched tuned track（给所有可训练基线等量搜索预算）成本高，v1 只跑 canonical configuration，且在报告里明确标注这一限制。

**一处保留意见**：研究员主张"不使用加权总分把 IC/Sharpe/MDD/turnover 压成一个数"。这条在**结算层**完全采纳——我们的主表就是逐指标分列的，不存在总分。但**呈现层**的 profile 图需要每阶段一个标量才画得出三范式画像，这是论文叙事的核心图。折中办法：该标量按 §1.2 的锚定归一定义、权重预注册并公示、图注明确标注"用于形状比较，逐指标记录以主表为准"，且任何结论性断言只引用主表数字而非该标量。这个处理方式与他的关切不冲突——他反对的是用总分掩盖分歧，而不是反对可视化聚合。

## 6 需要立即传达给 Claude Code 的冻结项（M2/M3 在飞）

以下五项影响正在进行的卡 2.2、2.3 与 3.2，晚一步就要返工：

5. 卡 3.2 的题目蓝图按 §4 的 COR/ROB/ECO/OPS 四族覆盖，自由发挥题在 S3–S5 各留位置（v1.0 冒烟阶段每阶段先各 1 道）。
