# 回测声明 v3（卡 2.2b 的契约）

**这份文件是实现 B 的唯一输入。** 顺序是硬要求：先有声明，再有实现。
实现 B **不得**阅读 qlib 的 `exchange` / `executor` / `strategy` 源码 ——
照着 qlib 写会得到同一实现的两个副本，ε 会虚小。

**ε 的用途决定了这件事**：ε 用来判 agent 交付的回测结果是否落在 gold 的 ε 带内，
而 **agent 不会用我们的 qlib 代码、会自己实现撮合**。
所以 ε 必须覆盖「两份独立实现同一份声明会差多少」——环境噪声与这件事无关。

> **v2 相对 v1 的改动**（全部来自 v1 那轮实测暴露的问题）：
> ① `rebalance_frequency` 升为**必填、无默认**；② 输入面板补上「掉出指数但仍在交易」的行；
> ③ A-7 由协议裁决；④ A-5 定死；⑤ 新增退市强制清仓规则。

## 1. 数据面

输入：一份纯 parquet（**不需要 qlib**），列：

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `date` | str `YYYY-MM-DD` | 交易日 |
| `code` | str 如 `SH600000` | 标的 |
| `close` | float64 | **后复权价**；`NaN` = 当日无价 |
| `factor` | float64 | 后复权因子（**原始价 = close / factor**）|
| `in_universe` | bool | 当日是否在 `csi300` 成分内 |
| `has_price` | bool | 当日是否有价（= `close` 非 `NaN`）|
| `is_delisted` | bool | 当日是否已过该标的**最后一个有价日**（真退市）|
| `signal` | float64 | 当日 gold 因子值 `qlib_alpha158.ROC20`；可能为 `NaN` |

**四种形态必须分开处理**（v1 的教训：前两种曾混成同一形态）：

| `in_universe` | `has_price` | `is_delisted` | 含义 | 规则 |
| :---: | :---: | :---: | --- | --- |
| ✅ | ✅ | ❌ | 正常成分股 | 可买、可卖 |
| ❌ | ✅ | ❌ | **掉出指数但仍在交易** | **不可买；已持有的可以按市价卖**，也可继续持有并按 `close` 估值 |
| any | ❌ | ❌ | 停牌（仍上市） | 不可买、不可卖；按**最后一个有效 `close`** 估值 |
| any | ❌ | ✅ | **真退市** | 见第 4 节的强制清仓规则 |

窗口：`2019-01-02` … `2026-07-03`（右端 = 持有期 20 日的可用求值右端）。
面板含 6 天暖机。

## 2. 策略声明

| 项 | 值 |
| --- | --- |
| 类型 | TopkDropout |
| `topk` | 50 |
| `n_drop` | 5 |
| **`rebalance_frequency`** | **必填，无默认** —— 取值 `daily` / `weekly` / `monthly` |
| **`first_rebalance_day`** | **必填，无默认** —— `window_start`（窗口首日额外算一次调仓） / `first_period_end`（等到第一个周末/月末）|
| 调仓时点 | 收盘后（用当日收盘信号，成交价用当日收盘价）|
| 成交价 | `close`（后复权）|
| 结算 | T+1：当日买入次日才可卖 |
| 初始资金 | 100,000,000 元 |
| 交易单位 | 100 股 |

**`rebalance_frequency` 的语义**：

- `daily` —— 每个交易日调仓；
- `weekly` —— 每周**最后一个交易日**收盘后调仓（通常是周五，遇假期顺延到该周最后一个交易日）；
- `monthly` —— 每月**最后一个交易日**收盘后调仓。

**非调仓日不产生任何成交**，持仓随价格漂移（第 4 节的退市强制清仓除外）。

> ⚠ **这个字段没有默认值是刻意的。** v1 的声明漏写了调仓频率，三份独立实现
> 都默认取了 `daily` —— 而周频/月频同样符合原声明字面，换手与费用会差**一个量级**。
> 缺失即欠定：日后 S7 的 TaskSpec 里它同样是必填，**缺失就是第五探针（欠定语义）要抓的东西**。

> ⚠ **`first_rebalance_day` 为什么也必须必填**（v2 实测暴露）：
> A-12「首日建满」与第 2 节「非调仓日不产生任何成交」在
> **窗口首日不是周末/月末时直接矛盾**。选 `window_start` 还是 `first_period_end`，
> 会让 `monthly` 的建仓时点差一个月、三档的可比性也不同 ——
> **它是下一个 N-1**。三份 v2 实现都自行选了 `window_start` 并各自说明了理由，
> 但那是它们的判断，不是声明给的。


## 3. 费率声明

| 项 | 值 |
| --- | --- |
| 买入费率 | 0.0005 × 成交金额 |
| 卖出费率 | 0.0015 × 成交金额（已含印花税）|
| 单笔最低费用 | 5.00 元，粒度 = **每标的每方向每日一笔** |
| 滑点 | 不计 |
| 费用基数 | **实际成交金额**（= 成交价 × 成交股数），**不是**目标金额 |
| 取整与费用的次序 | **先整手取整，再按取整后的成交金额算费用** |
| 取整容差 | 允许 **≤ 1 手**的取整容差（避免浮点边界上差一手）|
| 清仓例外 | **清空一个头寸时不受整手约束** —— 否则后复权口径下的碎股永远清不掉 |
| 零成交 / 被拒单 | 取整后 0 股、或被涨跌停/停牌拒掉的订单**不算一笔**，**不收**最低费 |
| 费用预留 | **目标金额先除 `(1 + 买入费率)`**；实现若改用「事后按现金裁剪」，差异落在 ε 带内 |
| 滑点参数 | `impact_cost = 0.0`（显式写死，使「滑点不计」有可核条目）|

## 4. 可交易性与退市

| 情形 | 规则 |
| --- | --- |
| 停牌（`has_price=False` 且 `is_delisted=False`）| 不可买、不可卖；按最后一个有效 `close` 估值 |
| 涨跌停 | `|close / pre_close − 1| >= 0.095` → **不可买也不可卖** |
| `pre_close` | 该标的**前一交易日的最后一个有效 `close`**（同为后复权）。若该标的在窗口内此前从未有过价，则 `pre_close` 未知 → **不视为触及涨跌停** |
| 掉出指数（`in_universe=False` 且 `has_price=True`）| **不可买；已持有的可以卖**（受涨跌停约束）|
| **真退市**（`is_delisted=True`）| **在 `is_delisted` 变为 `True` 的第一天**，按该标的**最后一个有效 `close`** 强制清仓；**计卖出费用**；**计入换手分子**；不受涨跌停约束、不占用 `n_drop` 名额 |

## 5. 组合构建（协议裁决，不是口味）

**A-7 —— 目标组合与执行分离**：

1. **目标层**：在「当日有有效 `signal` 的成分股」上按信号排序取 `topk`，形成**目标组合**。
   **这一步不看可交易性。**
2. **执行层**：可交易性在这里生效。买不进的**留空**，
   **持仓数可以少于 `topk`**。

> **理由（写进声明，因为它是协议要求而非偏好）**：协议规定 TargetPosition 是**执行边界** ——
> 它保存的是**意图组合**，不依赖已实现的执行；订单生成与交易限制归**下游执行环境**。
> 「从当日可交易集合里选 topk」把执行约束提前混进策略层，
> 正是协议要分开的两件事。

**卖出**：卖出「已跌出当日目标组合」且当日可卖的持仓，至多 `n_drop` 只
（不足 `n_drop` 就少卖；`n_drop` 是**换手上限**，不是「必须换掉的只数」）。

**买入**：从目标组合中**未持有且当日可买**的标的，按信号从优往下取，补齐到 `topk`。

**资金分配**：当日**可用现金**在本次买入标的间**等额**分配（含费用预留）。

**再平衡**：**不做**每日再平衡；持仓只在调仓日的 drop/add 时变动。


## 5b. 持仓记账口径（v3 定死，不再是歧义）

**问题**：声明同时要求「按后复权 `close` 估值」与「整手取整用原始价」，
但没说**持仓到底存哪一种**。两种存法在**除权日**的收益差异是**系统性的**
（分红是否隐含再投资），不是舍入噪声 —— 在 A 股这会污染**几乎所有**跨除权日的持有期。

**裁定：持仓以「后复权份额」记账。**

```
市值        = 份额 × 后复权 close
买入时      真实股数 = floor(可用金额 × factor / (后复权价 × 100)) × 100
            份额     = 真实股数 / factor
持有期间    份额不变（≡ 分红自动再投资）
```

**理由**（决定性的一条，不是口味）：本回测的输入**只有** 后复权价 + `factor`，
**没有现金分红流水表**。若改成「存真实股数、按原始价估值」，
除权日组合市值会掉一段而**没有任何东西补回来** —— 分红收益被**凭空吃掉**。
在只有复权价可用的数据面上，「后复权份额恒定」是唯一自洽的口径。

**副产品**：这个口径下成交金额的两种算法**恒等** ——
`份额 × 后复权价 ≡ 真实股数 × 原始价` —— 所以第 3 节「费用基数 = 实际成交金额」无歧义。

## 6. 指标定义

设 `r_t` 为逐日组合收益率，`n` 为交易日数，`ANN = 252`。
总资产 = 现金 + 持仓盯市市值（**含现金**）。
`r_net_t = TA_t / TA_{t−1} − 1`；`r_gross_t` = 把当日全部费用加回后的同一比值。

| 指标 | 定义 |
| --- | --- |
| `ann_return_gross` / `ann_return_net` | `(1 + r).prod() ** (ANN / n) − 1` |
| `ann_vol_net` | `std(r_net, ddof=1) * sqrt(ANN)` |
| `sharpe_net` | `mean(r_net) / std(r_net, ddof=1) * sqrt(ANN)`（无风险利率 = 0）|
| `max_drawdown_net` | `nav = (1+r_net).cumprod()`；`min(nav / cummax(nav) − 1)` |
| `turnover_one_way_mean` | 逐日 `卖出金额 / 分母` 的均值 |
| `turnover_two_way_mean` | 逐日 `(买入金额 + 卖出金额) / 分母` 的均值 |
| `win_rate_net` | `mean(r_net > 0)` |
| `total_cost` | 全期费用合计 / 初始资金 |

**A-5 —— 换手分母定死为「当日交易前总资产」**（= 当日收盘价估值的持仓市值 + 现金，
成交发生之前）。这是 v1 里三份实现各写一种措辞的那个量，
现在选定其中一种并写死：**交易前**，不是「期初」也不是「上一交易日收盘」。

**收益率序列起点**：建仓当日**计入**序列（该日 `r_gross = 0`、`r_net` = 建仓费用的负值）。

**换手分子**：**含**首日建仓与退市强制清仓这两类非常规成交。

**末日**：**不**强制清仓。

## 9. 已知且**知情保留**的欠定项，与 A↔B 的**未归因残差**（都不是未解决缺陷）

这一节记两件**不同**的事。2026-09-03 之前它们被当成同一件事，那是错的。

### 9.1 A↔B 的未归因残差 22.69%

| 事实 | 值 |
| --- | ---: |
| A（qlib TopkDropout）与三份独立实现 B 的 `turnover_two_way_mean` 差 | **−0.51%** |
| 同两者的 `ann_return_gross` 差 | **+22.69%** |

**换掉的金额几乎一样、换的标的不同** —— 分歧**从任何交易强度指标上都看不出来**。

**这 22.69% 目前是「未归因残差」：成因未知。**
本节此前写的是「定位到 A-1 / A-2」，**该归因已撤回** —— 它是**排除法**得出的
（排除了费用口径与 `risk_degree` 之后把剩余项安给 A-1），**从未做过隔离实验**。

**隔离实验反而排除了 `sell_rule`（A-1）**：2026-09-03 的 materiality screen 在
**同一份实现内部**切换 `sell_rule` 的两种读法、其余一切不变，三份 B 的
`ann_return_gross` 相对差只有 **0.38%–0.45%**（daily ε=0.237%）——
**与 22.69% 相差约 50 倍，A-1 解释不了这个数。**

**残差仍是知情保留的**：不是待修的 bug，A 与 B 完全收敛也没有独立价值
（daily 档 ε 已 usable）。变的只是**我们不再声称知道它的成因**。

> ⚠ **给日后维护者**：这个 22.69% **不是 bug，不要顺手修掉**，
> 也**不要再把它写成 A-1 造成的**。
> `ops/test_underdetermination_guard.py` 锁的是**这个残差仍然存在**；
> 它变红说明有人改了 A 或 B —— **先去查什么变了**，不要直接改测试。

### 9.2 A-1 / A-2 仍然是知情保留的欠定项

**A-1 / A-2（`n_drop` 的卖出选择与买入补齐）不定死，是裁决，不是遗漏。**
qlib 卖「持仓中信号最差的 `n_drop` 只」，三份 B 卖「已跌出当日目标组合的」，
**两种读法都合理**，声明不裁决哪一种。

**为什么不定死**（签字裁定 2026-09-01，2026-09-03 复核后维持）：
它有**隔离实验实测背书**——单独效应 0.38%–0.45%，

是一条合格的欠定样本，定死它等于少一道题。

**改变的是它的地位**：它是一条**自身 material 的欠定项**，
**不再**是「A↔B 22.69% 的解释」。这两句话不能混用。

## 10. S7 出题与判据规则（由 ε 分档实测得出）

**① 容差按题面声明的 `rebalance_frequency` 取对应那一档。**
`daily` 档的 ε **不得**用来判低频题。

**② 低频题容差更宽 —— 与直觉相反，这里写明。**

直觉是「高频换手大、更难复现」，**实测相反**：

| 频率 | 调仓次数 | 换手三份互相差 | 毛收益三份互相差 |
| --- | ---: | ---: | ---: |
| `daily` | 1,818 | 0.001% | 0.158% |
| `weekly` | 385 | 0.086% | 5.233% |
| `monthly` | 92 | 1.202% | **19.252%** |

**分歧不在换手量上，在调仓时点上。** `monthly` 只有 92 次调仓，
「哪天算调仓日」这**一个**歧义就占 1/92 的影响；`daily` 有 1,818 次，个别错位被平均掉。
**低频不是「更简单更一致」，而是「每个决策点权重更大」。**

**③ `weekly` / `monthly` 两档当前 `usable=False`，这个状态保留。**
**不要为了让它们 usable 去放宽阈值。** 它们的超阈项
（`sharpe_net` 12.8%、`ann_return_gross` 19.3%、`total_cost` 9.1%）
本身就是「低频下声明欠定的影响被放大」的**证据**，与 A-1 一样有信息价值。

**④ 要出低频题，先补两样再标 ε**：`first_rebalance_day`（已升必填）
与该档的超阈歧义。**不要用 `daily` 档的 ε 去 judge 低频题。**
