# 同名算子的语义冲突：`ts_rank` 实证档案

**这份文件是 v1 唯一一组有据可查的、真实的同名算子语义冲突样本。**
它不是构造出来的陷阱 —— 是卡 2.1b 的双实现互检在 792 条因子上跑出来的。

裁定依据（签字人 2026-09-01 原话要点）：GeneQuant 协议明文规定**算子语义须绑定在因子定义上、不得由任何一方隐式补全**。评测方替因子库拍板一种归一化，等于自己犯了被测方要被判违例的错误。
所以 v1 走 **C**：把受影响的因子移出 τ 样本、单列、gold 标注「算子约定存疑」、S3 出题避开。

## 1. 机制

| 引擎 | `ts_rank` 实现 | 值域 | 实测（同一列 `volume`，窗口 32）|
| --- | --- | --- | --- |
| 面板求值器（`PanelFormulaEvaluator`） | `rolling(w, min_periods=w).rank(pct=True)` | `(0, 1]` | 0.031250 … 1.000000 |
| qlib 表达式引擎（`qlib.data.ops.Rank`） | `rolling(N).rank(pct=True)` | `(0, 1]` | 0.031250 … 1.000000 |
| **KunQuant**（`KunQuant.ops.TsRank`） | `num_less + (num_eq + 1) / 2` | `[1, w]` | WQAlpha35 实测 −0 … 14880 |

**三方里 KunQuant 是唯一的原位次序实现。** qlib 与面板求值器**恰好一致**（都用 pandas 的 `pct=True`），
但那是巧合而非约定 —— 因子定义里从没写过 `Ts_Rank` 该归一化到哪个值域。

### 分歧如何进入截面序

常数缩放不改变截面上的相对次序，所以**不是**每一条用 `ts_rank` 的因子都受影响。
受影响的判据是：`ts_rank` 的**绝对量纲**是否参与组合。实测归纳出四种形式：

| 形式 | 为什么改变截面序 |
| --- | --- |
| `1 - ts_rank(·)` | pct 下结果在 `[0,1)` 为**正**；原位下在 `[1-w, 0]` 为**负** —— 符号翻转 |
| `max(rank(·), ts_rank(·))` | `rank` 在 `[0,1]`；原位 `ts_rank ≥ 1` **永远赢**，`max` 退化成恒等 |
| `rank(·) + ts_rank(·)` | 两项量纲差 w 倍，和被 `ts_rank` 主导 |
| `pow(ts_rank(·), ·)` | 底数从 `(0,1]` 变成 `[1,w]`，指数为负时单调性反转 |

反之，`rank(ts_rank(·))`（被截面 rank 重新归一）与纯常数缩放（如 `-1 * ts_rank(·)`）**不受影响**。

## 3. 可直接引用的两个案例（进论文）

### 3.1 WQ101 `alpha073`：`max` 的两个操作数必须同值域

原文公式：

```
(max(rank(decay_linear(delta(vwap, 4.72775), 2.91864)), Ts_Rank(decay_linear(((delta(((open * 0.147155) + (low * (1 - 0.147155))), 2.03608) / ((open * 0.147155) + (low * (1 - 0.147155)))) * -1), 3.33829), 16.7411)) * -1)
```

KunQuant 实现：

```python
def alpha073(self: AllData):
    p1=rank(decay_linear(delta(self.vwap, 5), 3))
    p2=ts_rank(decay_linear(((delta(((self.open * 0.147155) + (self.low * (1 - 0.147155))), 2) / ((self.open *0.147155) + (self.low * (1 - 0.147155)))) * -1), 3), 17)
    return -1* Max(p1, p2)
```

| 约定 | `rank(decay_linear(delta(vwap,5),3))` | `ts_rank(decay_linear(...),17)` | `max` 的结果 |
| --- | --- | --- | --- |
| pct（`(0,1]`） | `[0,1]` | `(0,1]` | 两者竞争，`max` 有意义 |
| 原位（`[1,17]`） | `[0,1]` | `[1,17]` | **`ts_rank` 永远赢，`max` 退化成恒等** |

实测秩相关 mean ρ = **+0.3866**（2,660 个交易日）。

**结论**：把归一化的截面 `rank` 与 `Ts_Rank` 放进同一个 `max`，只有当两者都在 `[0,1]` 时公式才说得通。原文未声明值域，两种实现都「合法」，而它们算出的**不是同一个因子**。

### 3.2 WQ101 `alpha035`：`1 - Ts_Rank` 在原位约定下符号翻转

原文公式：

```
((Ts_Rank(volume, 32) * (1 - Ts_Rank(((close + high) - low), 16))) * (1 - Ts_Rank(returns, 32)))
```

KunQuant 实现：

```python
def alpha035(self: AllData):
    return ((ts_rank(self.volume, 32) *
                (1 - ts_rank(self.close + self.high - self.low, 16))) *
            (1 - ts_rank(self.returns, 32)))
```

| 约定 | `1 - Ts_Rank(x, 16)` | `1 - Ts_Rank(returns, 32)` | 两项之积 |
| --- | --- | --- | --- |
| pct | `[0, 1)`，**非负** | `[0, 1)`，**非负** | 非负 |
| 原位 | `[-15, 0]`，**非正** | `[-31, 0]`，**非正** | 非负但量纲差 ~500 倍 |

实测秩相关 mean ρ = **-0.5009**，即两个实现给出**接近反向**的截面排序。

**结论**：`1 - f(·)` 这种写法把 `f` 的值域**隐式声明**成了 `[0,1]` —— 但那只是读者的推断，公式本身没写。这正是「名字相同不等于语义相同」最干净的一个实证。

## 4. 顺带查出的第二类缺陷：字段错位（不是算子语义）

`worldquant_101.038` 的 mean ρ = +0.8955，形式上却判为「被 `rank()` 包住、截面序不变」。
查下来根本不是 `ts_rank` 的事：

| | 表达式 |
| --- | --- |
| 源方言原文 | `((-1 * rank(Ts_Rank(**close**, 10))) * rank((close / open)))` |
| KunQuant 实现 | `-1 * rank(ts_rank(self.**open**, 10)) * rank(inner)` |

**KunQuant 在 `ts_rank` 的实参上用了 `open`，而公式写的是 `close`。** 这是字段错位，
与归一化约定无关，属于参考实现的缺陷。已随本文件登记。

**扫描的覆盖限度（必须写清）**：为此写了一个 (算子, 字段实参) 对的比较器，
并**先在 `.038` 上验过判别力**（抓不到就不出结论 —— 第一版比的是字段**集合**，
对「同一组字段换了位置」恒返回 0，是一次空转的扫描）。
扣掉 `adv20 → sma(volume,20)` 这类已知良性展开后仍有若干命中，
但**凡是有实测 ρ 的，除 `.038` 外全部 ρ = +1.0000**，即比较器的剩余命中是假阳。

⚠ **真正的限度在别处**：82 条 KunQuant 因子里只有 **51 条**有第二实现可比，
另外 31 条**无法用互检裁定**。那 31 条里若有同类字段错位，本方法**看不见**。
这条限度写进 L5 适配赛道的题源说明。

## 6. 成稿形式：「因子名或表达式不足以确定其计算」的双重实证

> 这一节是给论文直接引用的。两个案例来自同一次双实现互检，
> 它们证明的是**同一件事的两个层面**。

同一个因子名，在两个**成熟的、被广泛使用的**实现之间，可以在两个完全不同的层面上分叉：

**第一层：算子语义未被绑定。** `Ts_Rank` 在一个实现里归一化到 `(0, 1]`，
在另一个里返回原位次序 `[1, w]`。**两边都没有错** —— 原文公式从未声明该算子的值域。
错的是「同名即同义」这个假设。
WorldQuant 101 的 `alpha073 = max(rank(·), Ts_Rank(·, 17))` 把归一化的截面 `rank`
与 `Ts_Rank` 放进同一个 `max`，只有两者同值域时才说得通；用原位次序时 `ts_rank` 永远赢，
`max` 退化成恒等。`alpha035` 的 `1 - Ts_Rank(·)` 在 pct 约定下非负、在原位约定下非正 ——
**符号翻转**。实测逐日截面秩相关 mean ρ 分别为 **+0.3866** 与 **−0.5009**。

**第二层：实现读错了输入。** `alpha038` 的源方言写 `Ts_Rank(close, 10)`，
而实现写 `ts_rank(open, 10)` —— **`close` 被写成了 `open`**。
这一层与约定无关：**有一方就是错的**。实测 mean ρ = **+0.8955**。

**两层在产物层面表现完全一样**：都能算出数、都能跑通、数值分布看起来正常、
没有任何异常值或报错。区别只有在**拿另一个独立实现去对**的时候才显形 ——
而且第二层还更隐蔽：它的 ρ = 0.90 比第一层的 −0.50 更像「正常的实现差异」。

**方法论后果**：
一份因子的**名字**（`WQAlpha38`）与**表达式**（`Ts_Rank(close,10)`）**都不足以**确定它的计算。
名字不够，因为同名算子语义可以不同；表达式也不够，因为表达式到实现之间还有一次翻译，
而那次翻译可能读错字段。
可复现的因子定义必须同时绑定：**算子语义（含值域）**、**输入字段**、以及**一份可执行的参考实现**；
三者缺一，两个都自认为正确的实现就会算出不同的因子而互相不知道。

**这也是我们自己差点犯的错**：评测方若替因子库拍板一种 `ts_rank` 归一化，
就等于自己做了协议禁止被测方做的事（隐式补全算子语义）。
v1 的处置是把受影响的因子移出 τ 样本并单列，而不是替它们做决定。
