## 1. 被测的是什么

GeneBench 的主假设是：**GeneQuant 协议的执行机制**能提升 agent 在八阶段量化研究链上的表现。
双臂对照要成立，两臂之间的差**必须只有这个机制**。

因此公平性在本项目里不是「对被测方好一点」，是一句**可证伪的等式**：

> **两臂的一切差异 == 干预本身。** 多一件是隔离失败，少一件是干预失败。

这个等式有两个方向，而**两个方向的失败形态完全不同**：

| 方向 | 名字 | 后果 | 会不会报错 |
| --- | --- | --- | --- |
| 协议臂**多**拿到了非协议的东西 | **隔离失败** | 结论虚高：把别的优势记到协议头上 | 不会 |
| 协议臂**少**拿到了协议该给的东西 | **干预失败** | 结论虚低：跑出「协议没用」 | **不会** |

两个方向都不报错，都跑得完，分数都照出。**所以每一条公平性规则都必须是「有东西会红」，
不能是「我们不会那样做」。** 这是本文所有条款的共同形状。

## 2. 两臂的定义与唯一允许的差异

`genetask/schema.py:32`：`ARMS = ("strict", "open")`。

| 臂 | 别名 | 拿到什么 |
| --- | --- | --- |
| `strict` | 协议臂 / GeneQuant 臂 | 题面（记号式） + **协议工件**（`ops/protocol/geneprotocol_v1/MANIFEST.json` 的封闭文件集） |
| `open` | 裸臂 | 题面（自然语言式），**无协议工件** |

**设计允许的臂间差异，穷举，只有两项**：

1. **题面的表达形式**：strict = `key=value` 记号 + 中文括注；open = 自然语言 + （字段名、接口值）。
2. **协议工件的有无**：只有 strict 臂有，且**恰好是清单列出的那些**（§6.2）。

**除此之外的一切，两臂必须相同。** 断行不属于设计允许的差异（卡 3.1 §7f 五、六）；
超时与镜像不属于（§6.3）；环境变量除 `GENEBENCH_ARM` 外不属于（§6.3）。

**臂（arm）与配置（config_id）是两个正交轴**（卡 4.3 §6.3）。等价性断言只在
**同 `config_id`、不同 `arm`** 的两次运行之间成立。跨 config 比较不是双臂对照，是另一个实验。

> **与《指标规格 v1》§0 的口径差**：该文写 `a ∈ {裸, GQ, 文档}`（三臂）。
> **v1 实现的是两臂**（`ARMS` 两项，注入器契约按两臂写）。第三臂若将来加入，
> 本文 §2 与卡 4.3 §6.2 的等号都要按三臂重写 —— 这不是加一行的事，先在这里记一笔。

## 3. 题面层：信息分配与保守性

### 3.1 语义等价的定义写死在题面层

卡 3.1 §7b 一裁定：两臂用**同一开头句**「按下列声明完成任务」；
**语义等价的定义 = 声明项、约束、产出位置、输出格式、校验串**这五项两臂都有。
**GeneQuant 臂多出的信息是干预本身，只能经协议工件抵达，不许经题面抵达。**

由此产生 **E5**：题面出现「契约 / 协议 / schema / 规格」这类**指针词**即红 ——
指针把信息推到题面之外，而题面之外只有一臂够得着。

### 3.2 保守性原则：拿不准就两臂都给（承接卡 3.2 §3d）

两臂共享的 `/task/<stage>.json` 在 `declarations.required` 里列出**全部**声明字段名
（**含本题欠定的那个**）及其枚举。这是三态标记的必要条件 —— agent 得知道该给哪个键写 `unresolved`。

**裸臂（open）因此拿到**：

| 裸臂拿到 | 来源 |
| --- | --- |
| 输出格式（信封必含、payload 必含与子字段、类型） | 固定槽 `output_format` + 共享 `/task/<stage>.json` |
| **必填字段清单**（含欠定字段的键名与枚举） | 共享 `/task/<stage>.json` |
| **「不补默认值、标 unresolved」指令** | 固定槽 `no_default_fill`（**两臂逐字相同**） |
| 全部任务级信息与可见环境信息 | 固定槽（as_of / window / universe / inputs / endpoints / artifact_path） |

**剩给协议臂的只有执行机制**：三态强制、validator 的结构化反馈、修复回路。

**这不是缺陷，是保守设计。** 我们把协议的**语义内容**也给了裸臂，
因此测出的差异只能归因于**执行机制**，而不能被解释成「协议臂多知道了协议要求什么」。
**它让协议臂的优势主张更难被质疑，而不是更容易。**

**保守性的方向纪律**：拿不准一件东西属「语义内容」还是「执行机制」时，
**默认给两臂**。给多了只会让我们要证明的东西更难证；给少了会让它变得虚假地容易。
两种错误的代价不对称，所以默认值不对称。

**格式 vs 执行的切分线**（卡 3.1 §7g 第三批、卡 3.2 §3d）：
**键名是声明项的身份，属格式不属执行。** open 臂要产出 `declarations` 本来就必须完成
「中文口径 → 键名」这个映射，给键名**不抬高它的能力上限**，只消除一次无关的翻译损耗。
不给的后果是**信息相同、可达性不同**，探针读数的臂间差里会混进「发现难度」——
而且方向**偏向协议臂**，虚增我们要证明的东西。机械化为 **E10 / E10b**。

**「事后分层统计」不是缓解手段。** 它只是补丁，在证据链上留洞。
「agent 是否枚举过必填字段清单」的分层统计**保留为诊断项**，不承担缓解职责。

### 3.3 E1–E13：每条规则封的是哪一种不对称

规则全文与负例在卡 3.1 §3 / §4 / §7b–§7h，此处只给**角色**，不复述实现。

| 规则 | 封什么 |
| --- | --- |
| **E1** | 槽位集相等、每槽恰一次 —— 结构层的对称 |
| **E2** | 欠定字段的**字段名 / `field=` 记号 / 全部取值 / 概念词**在两臂零命中 —— 防题面泄漏答案（含**组合判据**：处置动作 × 判别依据同小句 → 交签字人裁） |
| **E3** | 固定项两臂都在，**且比代入的值**（不是比渲染串）—— §7h 修：只查「在不在」时六个槽实测全沉默 |
| **E4** | 概念覆盖，**只扫槽位外文本** —— §7h 修：扫全文时 23 个概念里 13 个被机器生成的槽位文本满足，14 题永不可能变红 |
| **E5** | 指针词（契约/协议/schema/规格）即红 —— 指针指向的东西只有一臂够得着 |
| **E6** | 情态/量词**按类别**比（禁止/义务/许可/排他/界量）→ 进签字表 review 列，**不自动判红**。**类别相同 ≠ 强度相同**（「不得」vs「不要」） |
| **E7** | **结算方式**词汇与**族标签**即红。原则：**目标可以说，结算方式不说**。升级理由：题面说「和参考实现比」→ agent 猜 qlib → qlib 的卖出规则正是 A-1 两种读法之一，与 `TopkDropout` 叠加**等于把答案给了两次** |
| **E8 / E8b** | 端点路径、文件路径、`k=v` 三个集合两臂相等；正文端点 ⊆ 端点槽 —— 可见环境信息不得只给一臂 |
| **E9** | `declared ∪ {probe_field}` **等于**该阶段契约必填集 —— 声明集由**产出要求**反推完整性（D-13） |
| **E9b / E9c / E9d / E9d2 / E9d4** | 探针字段的四条有效性前提，见 §4 |
| **E10 / E10b** | 键名可达性：strict 的 key 集合 == open 的字段名集合；正文产出**键路径**集合两臂相等 |
| **E11 / E12 / E12b** | **显著性**：探针句两臂都独立成**段**；每个槽两臂都独立成行；段落数与探针句所在段序相同。断行不属于设计允许的臂间差异 |
| **E13** | 题面不得要求 agent **筛选/省略/修饰自己的产出记录**（`RECORD_FIELDS` × `FILTER_VERBS`，带否定前缀放行）—— 见 §5.3 |
| **C1 / C1b / C1c** | 控制金丝雀每臂恰一次、两臂同值、**必须是裸行**（不得附加回显义务） |

**E1–E13 只管题面。环境等价归卡 4.3（§6）。** 卡 4.3 §1.3 实测的五条环境不等价
（共用 run dir / 共用 compose 项目 / 共用子网 / run_id 覆盖 / 题面来自代码），
**E1–E13 一条都管不到**。这条边界要写清楚，否则会有人拿「E1–E13 全绿」去证明双臂等价。

### 3.4 机械规则的边界：人工签字不可撤

**卡 3.1 §7b 的标题就是结论：E1–E4 全过，而原文有五处实质不对称。**
之后每一轮都重复了这件事：§7c 15 处、§7d 五处、§7f 三类、§7g E13、§7h 38 处规则自身的洞。
**零发现的那一轮还没出现过。**

因此：

1. **机械规则每轮都在追上一轮人眼抓到的模式**，它是人工签字的**下界**，不是替代。
2. **人工签字不能撤。** 探针题**逐题**人工签字；规定题每阶段抽 1 道贴签字人过目（§3.5 的分层）。
3. **复审员的默认立场必须是否证**（default-refute），不是「找不到问题就算过」。
4. **复核者的「未判」与「驳回」分开记**（写进 `redteam_protocol.md`）。

**三条纪律**（卡 3.1 §7g，与规则并列，不可省）：

1. 改任何一臂的句子，**先写下这句话断言了什么**，再确认另一臂的对应句断言同一件事 ——
   而不是只确认「词都在」。**修复动作本身会引入新的不对称**：同一道题上出现过三次，每次都由上一次的修复引入。
2. 每条「两臂对称」的裁定要问三遍：**声明段**成立？**产出段**成立？**版面**上成立？**反方向**成立？
   前两轮各漏了一个方向。
3. **规则本身的盲区要主动找。** 现有规则几乎全是「一臂对、一臂错」的形态判据（集合差、逐字比、段序比），
   **它们挡不住两臂一起错**。凡比**派生量**（集合、计数、序号）的规则都要问一句
   「两臂一起错时它还报吗」。找法不是做两臂 diff，而是**拿评分器的每一条扣分项去问
   「题面有没有在教 agent 规避它」** —— 题面与评分器的对照，是两臂对照查不到的那一维。

**规则沉默必须被观测到，不能被推断。** §7h 那 38 处每处都配了一段实跑过的负例；
反向教训同等重要 —— 有四个词是收进来又退回去的（收进来会把题面正词判红）。

### 3.5 审查强度分层

| 题型 | 数量 | 审查 |
| --- | --- | --- |
| 探针题 | 8 | 机械规则全过 + 对抗复审 + **签字人逐题人工签字** |
| 规定题 | 32 | 机械规则全过 + **每阶段抽 1 道**贴签字人过目，其余按规则放行 |

**理由**：探针题的主读数是「标 `unresolved` 还是静默挑一个值」这一**二值行为**，
臂间任何措辞差异**直接**改它的概率；规定题的读数是产出与 gold 比数，
措辞差异要先改变计算过程、再穿过 ε 带才看得见，**后果小一个量级**。

## 4. 探针的有效性前提（公平性的另一半）

一个不合格的欠定探针不是「没测到东西」，是**罚错了人**。四条前提，缺一不可：

| # | 前提 | 反例与后果 |
| --- | --- | --- |
| **E9b** | **material**：该字段在本题参数下**真的会改变数字**（`FIELD_MATERIAL_WHEN` 静态前提） | `first_rebalance_day` @ daily：**实测 9/9 项逐位相同**。静默补全不改变数字 → 探针**量不到**危害；而「推理出该字段在本题参数下无关、于是继续做题」的 agent 被判静默补全 → **探针罚掉了最正确的推理**（D-12）。协议原文限定 *financially material* |
| **E9d** | **无规范化领域默认**（`CANONICAL_DEFAULT_FIELDS`） | `lot_size`（一手 100 股）、`calendar_id`（SSE）：agent 都会填，且**填对**。静默补全**无害且正确**，探针罚的是领域常识，且**演示不出任何东西** |
| **E9d2** | **独立实现实测会分叉**（`DIVERGENCE_EVIDENCE`） | 「在我们的参考实现下会分叉」≠「对任何合理实现会分叉」。题源必须是卡 2.2b 的**实测歧义清单**，不是从声明集里挑一个藏起来（D-14） |
| **E9d4** | 可行值**不得与固定槽内容重叠** | `permitted_operations` 的取值就是端点名，而「可用端点」槽里写着它 —— 欠定它必被 E2 判成题面泄漏 |

**动态锁 E9c**（`probe_materiality_verified`）：未经 oracle **逐可行值实测**的探针字段只许 `draft`。
门槛挂在**落盘动作**（`write_task`）上，不挂在 `status != 'draft'` 上 ——
§7h 实测：`build_task` 硬编码 `draft`，挂在状态上的锁**在生产路径上永不触发**。

**materiality screen 的跑法**：**A + 三份 B 各跑一遍**（`IMPLEMENTATIONS`），
任一实现超 ε 带即 material；同一取值下的跨实现分叉单记 `cross_impl_divergence`。

**screen 自身的判别力必须被证明，不能被假设**（与 N1 / O1 / `assert_mutated` 同族）：

| 门 | 判据 | 2026-09-03 实测 |
| --- | --- | --- |
| **Gate 0** | **未打补丁**的沙箱副本必须复现快照产物（harness 自证不改行为） | 通过，最大相对差 **1.5e-14**（BLAS 归约序的浮点噪声）。**产物不是逐字节可复现的** —— 这条要写进论文 |
| **Gate 1** | 打了补丁、开关取**各自的原读法** → 与 Gate 0 **逐位相同**（补丁中性） | 通过 |
| **判别力自检** | 已知 immaterial 的字段必须被判成 immaterial | `first_rebalance_day` @ daily：**9/9 项逐位相同 → immaterial**，通过 |
| **阳性** | 已知 material 的字段必须被判成 material | `sell_rule`：三份 B 的 `ann_return_gross` 相对差 **0.38%–0.45%**（daily ε = 0.237%），B1 **5 项** / B2 **6 项** / B3 **6 项**指标超带 → **material** |

**v1 的诚实边界（N-39，必须写进论文，不许含糊）**：
卡 2.2b 记的 A↔B 毛收益差是 **22.69%**，而在**同一份实现内部**切换 `sell_rule` 两种读法的隔离实验
只给出 **0.38%–0.45%** —— **相差约 50 倍。A-1 解释不了 22.69%。**
原结论「剩余差异定位到 A-1 / A-2」是**排除法**得到的（排除了费用口径与 risk_degree），
**从未做过隔离实验**；隔离实验现在做了，结论不成立。

这条**不影响 `sell_rule` 当探针字段**（它是 material，实测在案），但它影响两件事：
① **ε 标定的解释** —— ε 是否吸收了未登记的实现差异；② 卡 2.2b **归因段的可信度**。
相关的 **N-38** 是一个现成的候选来源：`impl_v2_b1.py:153` 与 `impl_v2_b2.py:147` **强制首日建仓**，
而 `impl_v2_b3.py:126 rebalance_days` **没有这一步**；日频下三份掩码全 True 故不可见，
**周频/月频才显现** —— 那两档 `epsilon_dual_{weekly,monthly}.json` 的 `usable=false` 可能与此同源，**并档前必须查**。

**版本纪律**：把歧义字段写进契约会**消灭它自己的证据**（实现照声明执行，分歧消失）。
所以标定与分歧实测钉死在加该字段**之前**的契约版本（`S7_CONTRACT_VERSIONS`：标定与 A-1 实测钉 **1.0**，出题用 **1.1**），
A-1 状态锁当**跳闸开关** —— 它变红即版本没隔离好。

## 5. 结算面的公平性

### 5.1 判据先于被判之物（D-11）

**凡「一方产出、另一方评判」的结构，评判的判据必须先于被评判之物落盘，
且产出方看不到判据的实现细节。顺序不能反，也不能同时。**

这不是流程洁癖：**度量本身的定义依赖于这个顺序**。ε 定义为「独立实现之间的差」，
独立性由顺序保证；探针敏感度定义为「被污染的模型能答得出」，不被判卷牵着走由顺序保证。
**顺序错了，数还能算出来，只是量的不是那个东西。**

落地可从 git 历史核对：`ops/specs/backtest_contract.md` 的版本号早于 `reference/backtest_b*.py` 的首次提交；
`reference/memory_probe.py` 早于任何一道真题。

### 5.2 评分器不看臂，validator 不计分

* 评分器由 benchmark 侧**独立重实现**协议的 V_k（《指标规格 v1》§0.5：validator 不计分原则的条文落点）。
* 评分器的输入里**没有 `arm`**。协议臂的 validator 与修复回路属**被测系统侧行为**，
  计分裁决属 **benchmark 侧**，两者并行不悖。
* **scorer 与 gold 永不挂进 agent 容器**（容器边界口径，v1.0.16 起；旧表述「永不进执行面」见下方注）。oracle 不进容器（N-34），
  代价是「验证验证器」报告里 S8 越权探针与 egress 侧前视探针标 `partially_verified` 而非 `verified` ——
  **写成报告脚注，不假装是 verified**。

### 5.3 验行为不验申报

《指标规格 v1》§1 的设计原则一句话：**验行为不验申报**。
日历违例抽样 20 个交易日做实际对齐核验（申报可造假，行为不能）；
复权违例用指纹法核验实际口径与申报是否一致；前视违例由网关日志直接结算，不依赖产物申报。

**E13 是这条原则在题面侧的对偶**：题面不得要求 agent 筛选、省略或修饰自己的产出记录。
它抓的是一个**两臂一起错**的形态 —— 两臂**同时**写「只列合法的迁移」时 E1–E12b 全绿、C1 全绿，
而校验器把非法迁移记 violation：**如实记录的被扣分、删掉的得分**。
合法性判定归评分器，题面只说「记录本轮发生的**全部** X」。
**副作用是好的**：一个尝试了非法操作并如实记录的 agent，正是我们要与「根本没尝试」区分开的那类。

### 5.4 状态锁：拒绝出数，而不是出 0

anchor 为 `pending` 时效果分结算**必须拒绝出数，而非出 0**（卡 3.1 §7 第 4 条）。
同族的还有五把锁（`ops/capabilities.json`）：`n33_bars_open_amount_vwap`、`s8_state_endpoints`、
`anchor_ladder_54`、`probe_materiality_verified`、`n23_index_instrument`、`provider_sha256_pinned`。
**锁未翻绿只许 draft / dry-run；翻锁必须先有对应测试翻转的记录。**

**出 0 与拒绝出数的差**就是公平性的差：0 会进宏平均、会被读成「这个配置在这道题上不行」，
而真相是「我们还没有能力给它判分」。

## 6. 环境层等价（卡 4.3）

### 6.1 环境等价归 4.3，题面等价归 3.1

卡 3.1 的 E1–E13 只保证**题面**等价。**环境**等价是注入器的责任，判据是**封闭列举**：

> 文件集、每个同名文件的 sha256、env、timeouts、image digest、provider 根。

**列举之外的差异没有覆盖**（宿主内核参数、CPU 调度抖动、镜像层缓存命中差异）——
这条写进 §7 已知边界，不假装解决。

两臂各自**独占** run dir（`run_id = f"{task_id}.{arm}.{config_id}.r{seq:02d}"`）、
独占 compose 项目、独占子网、**各持一份独立的 provider 副本**（PA-3）。
**两臂共享一份 provider 等于共享一个可写入口**，环境等价一旦破，双臂对照就不成立。

### 6.2 两臂差异必须是**等号**，不是包含号

**条款**：

```
files(run_strict/work)  \  files(run_open/work)  ==  PROTOCOL_ARTIFACTS      （精确相等）
files(run_open/work)    \  files(run_strict/work) ==  ∅
两侧同名文件：除 INSTRUCTION.md 外，sha256 必须**逐个相等**
```

**为什么这样才公平**：把它写成「差异 ⊆ {INSTRUCTION.md, 协议工件白名单}」时，
**少给** strict 臂一个协议工件也满足 ⊆。

而少给一件不是隔离失败，**是干预失败** —— 协议臂静默退化成半个裸臂，
**实验照跑、分数照出、日志干干净净**，结论会变成「协议没用」。
这正是 §1 那张表的第二行：**它不报错。** ⊆ 抓不到它，等号能。

三条子句各封一个方向，**缺一个就漏一个形态**：

| 子句 | 封的方向 | 漏掉它会怎样 |
| --- | --- | --- |
| `strict \ open == PROTOCOL_ARTIFACTS` | **两个方向一起封**：多一件 = 隔离失败；少一件 = 干预失败 | ⊆ 只封「多」，「少」全放行 |
| `open \ strict == ∅` | 裸臂不得有协议臂没有的东西 | 裸臂多一个残留文件 = 反向污染，同样不报错 |
| 同名文件 sha 逐个相等 | **第三种形态**：文件集相等而**内容不同** | ⊆ 与 == **都看不见它** —— 集合层面完全对称，字节层面两臂在跑不同的东西 |

**`PROTOCOL_ARTIFACTS` 的定义必须是封闭清单，每条带 sha256**
（`ops/protocol/geneprotocol_v1/MANIFEST.json`）。
**「协议工件 = 某个目录里当时有的东西」是不可接受的定义** —— 那个目录会长东西，
而它长出来的那天，等号会安静地跟着变，没有任何东西报错。

**验收**：卡 4.3 **T2**。假绿形态写在同一行里：**写成 ⊆ —— 少给协议工件也算过（F8）。**

### 6.3 `timeouts` / `image` 不按臂覆写

**条款**：

```
env(run_strict) Δ env(run_open) == {"GENEBENCH_ARM"}         （对称差，精确相等）
timeouts(strict) == timeouts(open)                            （逐字节）
image_digest(strict) == image_digest(open)                    （逐字节，且 ≠ 占位 digest）
```

`timeouts` 与 `image` 取自**同一份 X task.yaml**（`X_KEYS` 含二者），**不许按臂覆写**。
`command` **不写进 compose**，由镜像的 ENTRYPOINT 决定（IN-3）——
compose 里能写 `command`，就能给两臂写不同的 `command`，而 **E1–E13 一个字都管不到 compose**。

**为什么这样才公平**：因为这里的偏差是**同向的**。

随机偏差与同向偏差对实验的伤害**不是一回事**：

| 偏差类型 | 对结果做了什么 | 后果 |
| --- | --- | --- |
| 随机偏差（调度抖动、缓存命中） | 加大方差，把两臂的差**推向零** | 更难显著；伤害保守，方向对我们不利 |
| **同向偏差**（按臂改超时/镜像） | 直接改期望，**与被测假设同向** | **把结果排好序** —— 不是打散，是排序 |

裸臂时限短一点，得到的差异会被读成「协议提升了效果」。
**它不会把结果打散，会把结果排好序**（与卡 4.1 §4 对模型知识 cutoff 的论证同形：
同向偏差的失败形态是「分数静默地虚高，探针全绿」）。

**这条最容易被善意破坏。** 给两臂各自「合适的」超时是最自然的工程直觉 ——
协议臂要跑修复回路，看起来就该多给点时间。而**「合适」的判断依据正是被测假设本身**：
「协议臂需要更多轮次」这句话是待证结论，不是可以拿来配置实验的前提。

**公平不等于「两臂条件都够用」，公平等于「两臂条件的差只有被测变量」。**
超时若真的不够，**两臂一起加**，然后重跑两臂 —— 不是给一臂加。
镜像同理：两臂 digest 不同就是在跑两套依赖，环境等价当场破，**且 E1–E13 看不见**。

**验收**：卡 4.3 **T3**。假绿形态写在同一行里：**只比 env 的键集，不比值。**
配套 **P4b**：镜像 digest 不得是占位值 `sha256:` + 64 个 `0` —— 占位 digest 能过 lint 的正则，
却意味着**跑的是没钉住的镜像**，两臂各跑一次可能拿到不同镜像。

### 6.4 金丝雀：被动绊线，不要求回显

控制金丝雀 `GBC-C-` 每臂题面**恰好一次**、两臂**同值**，且**必须是裸行**（C1c）。
**要求 agent 回显的金丝雀就不是金丝雀。** `check_export` 只核每臂题面各出现一次，从不检查 artifact。

`GBC-C-` **零命中 = 扫描器坏了**，该次扫描无效（非空证明）。
执行面一律按**格式正则**扫，**不需要也不许**拿到 `gold_token` 明文 ——
**gold_token 的明文永远不离开 f01**。

## 6.5 被测配置的定性：**验收配置 ≠ 实验设计**（范围修正 2026-09-04）

`runner/registry.py` 里的三条 DeepSeek 配置
（`cfg-openhands-deepseek` / `cfg-codex-deepseek` / `cfg-rdagent-deepseek`）
是 **M6 构造验收**用的，**不是实验设计**。

「同一模型三种 harness」是**验收时固定模型效应**的做法 ——
让「链路跑通了没有」这个问题的答案不被模型差异搅进来。
它**不构成主实验的配置矩阵**：主实验要测什么、配几个模型、几个种子，
由 **M7 的实验设计文档**定，审定之后才启动网格。

**为什么要在公平性协议里写这句**：本协议第 1 节说「被测的是什么」——
如果读者在这里看到三条配置，会自然地把它当成配置矩阵。
一份验收配置被当成实验设计读，就等于宣称了一个我们没有做过的比较。
两者在代码里长得一模一样（都是 `Config` 实例），**只能靠这句话分开**，
所以它必须写在两处：这里，与 `registry.py` 的模块 docstring。

M6 阶段的**任何数字不进论文、不称主表**（实施稿 M6 节）。

## 6.6 臂注册表与指令变体臂的例外（卡 4.1）

**臂不再是常量。** 臂集合定义在 `genetask/arms.yaml`：每臂 `{id, kind, default,
phrasebook_column, equivalence, artifacts[], description}`。
`schema.ARMS` / `bundle.ARMS` 从它派生（import 期读，**缺文件即错**）。
加一个臂 = 改这份 YAML 与它引用的清单／文本文件，**不改任何 .py**。

### 6.6.1 三类臂，两套等价规则

| `kind` | 是什么 | 等价规则 | 例 |
| --- | --- | --- | --- |
| `baseline` | 裸臂。**恰好一个**，且必须 `default: true`。工件集合恒空 | E1–E14 的**参照**；它独有文件集必须为 ∅（§6.2 第二条子句） | `open` |
| `protocol` | 投放工件的臂。工件 = 一份或多份**封闭清单**（每条带 sha256）+ 一个 `work/` 下的挂载点 | 与 baseline **两两比**，E1–E14 全查 | `strict`、`doc` |
| `instruction_variant` | 只改题面措辞的臂。措辞落到某个既有列（`fallback_column`），再追加一段固定文本（`variant_text_file`）。工件集合恒空 | **只查 E1 / E2 欠定零泄漏 / C1**，其余按 §6.6.2 开例外 | `hint` |

**默认臂集合里必须至少有一个非 baseline 的臂** —— 只剩裸臂的集合不是对照实验，
而那种失败是静默的：分数照出、报表照排，只是「协议有没有用」这个问题再也没有被问过。
`genetask/bundle.py::load_arms` 在 import 期红，`ops/test_arms_registry.py::
test_registry_refuses_a_baseline_only_default_set` 钉住。

### 6.6.2 指令变体臂免掉哪些规则，为什么

**照查（不因臂类型放松）**：

| 规则 | 为什么不能免 |
| --- | --- |
| **E1** 槽位集与**顺序** | 题面说了哪些声明项 —— 变了就不是同一道题 |
| **E2** 欠定字段零泄漏 | 第五探针的题面屏蔽。漏一个字，探针测的就不再是静默补全 |
| **C1 / C1c** 金丝雀恰一次、且是裸行 | 绊线本身；一旦附带义务它就不再是绊线 |

**开例外（记进 `arms/equivalence.md` 的「非默认臂」段）**：
`E3 E4 E5 E6! E7 E8 E8b E10 E10b E11 E12 E12b E12c E13 E14 E15`。

**理由**：这十六条查的都是**「两臂题面同构」**（逐槽措辞落对臂、段落骨架一致、
「不补默认值」句在两臂同样显眼、键名两臂对称、技术标识符集合相等……）。
指令变体臂按设计**故意不同构** —— 它与参照臂的差异就是末尾那一段追加文字。
拿同构规则去查一个故意不同构的臂，得到的是一串必然的红，而不是信息。

**例外必须是可观测的，不是「顺便也过了」**：
`ops/test_arms_registry.py::test_variant_arm_still_checked_on_e1_e2_c1` 的第三段
断言「不开例外时它必然红」—— 如果哪天变体臂在全规则下也全绿，说明它已经退化成
参照臂的副本，那条断言会当场红。

**免掉的清单逐题落盘**：`reference/tasks/<set>/<id>/arms/equivalence.md` 的
「非默认臂（臂注册表 genetask/arms.yaml，公平性协议 §6.6）」一段列出每个非默认臂
免了哪些码。签字人看的是那张表，不是本文件。

### 6.6.3 主表上 instruction_variant 臂**单列**

`scorer/report.py` 的主表按 `(config_id, arm)` 聚合。
**instruction_variant 臂不与 protocol 臂放在同一个对照里**：

* `strict` vs `open` 回答的是「投放执行机制有没有用」；
* `doc` vs `open` 回答的是「只投放规则文档够不够」（同一个问句的弱化版，同轴可比）；
* `hint` vs `open` 回答的是「**换一句话说**有没有用」—— 那是题面层的变量，
  与工件层的干预不同轴。把它排进同一列，读者会把「提示涨了 3 分」读成「协议涨了 3 分」。

**落点**：`scorer/report.py::table_a` / `table_b` 的每一行带 `arm_kind`
（取自 `genetask.bundle.ARM_BY_ID`，认不出的臂记 `unknown` 而不抛 —— 历史 run 里
可能有已经删掉的臂名）；`to_latex` 按 `kind` 分块，`instruction_variant` 块的块首
逐条写出它免了哪些等价规则（`scorer.report.waived_rules_for` →
`genetask.render.WAIVED_FOR_VARIANT`，与 §6.6.2 **同源**，不是在报告器里再抄一遍）。
**判据**：`ops/test_4rt.py::test_table_a_carries_arm_kind`、
`test_latex_blocks_by_kind_and_names_the_waived_rules`。
（这条在 2026-09-07 之前是协议里写着而代码没做的：`scorer/report.py` 全文 grep 不到
`kind`，主表只按 `(config_id, arm)` 聚合 —— 红队 finding 4。）

### 6.6.4 一个新臂的投放集合是它自己的清单，等号照旧

§6.2 的三条子句对**每一个非 baseline 臂**成立，`PROTOCOL_ARTIFACTS` 换成
**该臂 `artifacts[]` 的展开集**（`runner/inject.py::arm_files`）：

```
files(run_<arm>/work) \ files(run_<baseline>/work)  ==  arm_files(<arm>)  ∪ 该臂的逐题规则
files(run_<baseline>/work) \ files(run_<arm>/work)  ==  ∅
```

两个 protocol 臂**可以共用同一个挂载点**（`doc` 与 `strict` 都落在 `work/protocol/`，
`README.md` / `contract.md` 还逐字节相同）。「别的臂的工件」这个禁止集因此要
**减掉本臂自己的**，否则 strict 臂会被 doc 臂的清单判成「出现了不该有的工件」——
一个只在加了第二个 protocol 臂之后才冒出来的红。

### 6.6.5 加一个臂之后要做的三件事（出集入口 / 本地自查 / 重冻）

「加臂只改这份 YAML，不改任何 .py」说的是**注册表**那一半。剩下三件事此前
没有任何一处文档写着，外部用户照手册做只能得到一个仍然是两臂的集（红队 2026-09-07）：

**① 出集要点名这个臂。** 出集入口默认只渲染 `default: true` 的那些臂（此前它**只能**出这些）；
非默认臂要在命令行上点名：

```bash
$PY ops/export_bundle.py <task_id> --staging <暂存根> --digest sha256:<64 hex> \
    --arms <干预臂>,open[,<新臂>]
```

**顺序是语义**：第一个臂被当成**干预臂**写进 `arms/equivalence.md`
（`packager.build_task` 的 `strict, open_ = rendered[arm_ids[0]], rendered[BASELINE_ARM]`）。
写成 `--arms open,<新臂>` 会得到一张 **open vs open** 的等价表 —— `ok=True`、
无 problems、两侧逐字节相同，而**什么都没查**。`export_bundle.check_arms` 现在当场拒；
`packager.build_task` 自己那一层还没拒（改它要推任务集版本，记在票据里）。
**判据**：`ops/test_4rt.py::test_export_refuses_baseline_first_arm_order`。

**② 本地核一遍，再上执行面。**

```bash
$PY ops/run_f02_a1.py --dry --bundle <B> --manifest <M> --config-id <cfg> \
    --arms <新臂>,open --provider-root /data/shared/genebench/snapshots/v1/qlib_provider \
    --run-root $TMPDIR/genebench_dry
```

`--dry` 只跑 P0–P9 与 `work/` 装配（不起容器、不调模型、不读凭据），跑完按 §6.2/§6.6.4
逐条比两臂的 `work/` 文件集与 sha，不等就退 1。**run 根必须在数据根之外** ——
`/data/shared` 之内会被 L-5a 判据 2 当场拒（挂载点不许落在湖里）。
**判据**：`ops/test_4rt.py::test_dry_run_root_refuses_data_roots`。

**③ 同版本重冻。** `genetask/arms.yaml` 在 `ops/freeze_v10.CODE_FILES` 里 ——
加臂之后工作树与已发布的冻结清单不一致，而 `frozen_ref` 刻意不硬比 `code` 段
（给打包器加个无关函数不该让已发通行证作废）。所以：

* 每张通行证现在都记 `arm_registry.{sha256, frozen_sha256, in_sync}`
  （`ops/export_bundle.arm_registry_freshness`），`in_sync=false` 是**可查**的；
  出集时 stderr 另打一行 `[黄]`。**判据**：
  `ops/test_4rt.py::test_passport_records_arm_registry_freshness`。
* 重冻命令（题面未变时**不推版本**，只重冻）：

  ```bash
  flock /data/shared/genebench/locks/heavy.lock \
      /data/shared/genebench/env/bin/python ops/freeze_v10.py --write
  ```

* **重冻会让所有已发通行证作废**：`code` 在 `ROOT_FIELDS` 里 → 根 hash 变 →
  注入器 P3 对所有旧 bundle 当场拒（`ops/freeze_v10.py` 的 REVISIONS 里
  逐字写着这条 consequence）。所以重冻要挑**没有在途 bundle** 的时刻做，
  并把已导出的 bundle 重新导出。这件事不能顺手做，它是一次发布动作。

## 7. 已知边界（写进论文的局限性一节，不假装解决）

1. **金丝雀只抓文件级原样搬运。** parquet → CSV 重序列化会丢 metadata，**零命中 ≠ 无泄漏**。
   内容级泄漏靠「oracle 不进容器 + `reference/` 0700」守，不靠金丝雀。
2. **环境等价的断言集是封闭列举**（§6.1）。列举之外的差异没有覆盖。

## 8. 变更纪律

1. **本文件的任何一条改动，都要同时给出它在哪个卡里的落点与哪个测试里的判据。**
   没有测试的公平性条款是一句愿望，不是协议。
2. **两臂对称的裁定要问三遍**（§3.4 纪律 2）：声明段？产出段？版面？反方向？
3. **凡比派生量的规则都要问「两臂一起错时它还报吗」**（§3.4 纪律 3）。
4. **删一条规则要有实跑过的反向证据** —— §7h 有四个词是收进来又退回去的，退回去的理由也留档。
5. **论文引用本文件的锚不许漂**：§2 / §3 / §4 / §5 / §6 / §7 的编号是对外接口，
   要加内容就加子节，不要重排一级编号。
6. **三类臂与它们各自的等价规则**（§6.6.1，卡 4.1 落地）：臂集合是数据不是常量，
   住在 `genetask/arms.yaml`。改臂集合要同时给出三样东西 —— 该臂的 `kind`、它适用哪一套
   等价规则、以及**它在主表上排在哪一块**。少给任何一样，臂就会以一个没人查过的身份进表。
   判据：`ops/test_arms_registry.py`。
7. **指令变体臂的例外必须是可观测的，不是「顺便也过了」**（§6.6.2）：`instruction_variant`
   臂免掉十六条同构规则，但 **E1 / E2 欠定零泄漏 / C1 照查**。免掉的清单逐题落盘在
   `reference/tasks/<set>/<id>/arms/equivalence.md`，签字人看的是那张表而不是本文件。
   `ops/test_arms_registry.py::test_variant_arm_still_checked_on_e1_e2_c1` 的第三段断言
   「**不开例外时它必然红**」—— 哪天变体臂在全规则下也全绿，说明它已经退化成参照臂的副本，
   那条断言会当场红。**删掉那一段断言等于把这条纪律删了。**
8. **主表按 `kind` 分块，不许把不同轴的臂排进同一列**（§6.6.3）：`strict` vs `open` 问的是
   「投放执行机制有没有用」，`hint` vs `open` 问的是「**换一句话说**有没有用」——
   后者是题面层的变量，与工件层的干预不同轴。同列排放会让读者把「提示涨了 3 分」
   读成「协议涨了 3 分」。落点 `scorer/report.py` 的 `arm_kind` 列与 `to_latex` 的分块，
   块首逐条写出该块免了哪些等价规则，且**与 §6.6.2 同源**（`scorer.report.waived_rules_for`
   → `genetask.render.WAIVED_FOR_VARIANT`），不是在报告器里再抄一遍。
   判据：`ops/test_4rt.py::test_table_a_carries_arm_kind`、
   `test_latex_blocks_by_kind_and_names_the_waived_rules`。
9. **本文件 §7 的已知边界与 `ops/reports/known_limits_v1.md` 不许互相矛盾**（卡 6.3 核对，2026-09-08）：
   两处各写各的会让读者按其中一处做判断。**已核对一遍**，两处一致且互补 ——
   §7 记的是**公平性机制自身**的边界（金丝雀只抓文件级、断言集是封闭列举、清单没有签名、
   产物不逐字节可复现…），已知限制表记的是**判据与数据面**的限制（TE 出不来、S4 的 ε、
   S7 的预算…），**没有一条同时出现在两处而说法不同**。唯一的交叠是 §7 第 9 条与
   已知限制表的「三臂」问题，两处都说：`doc` / `hint` 是 `default: false`，
   **不进任何既有出集**，默认出集仍是两臂。

## 附：红线 2 的口径在 v1.0.16 改过一次

**旧口径（v1.0.15 及以前）**：「答案面不上执行面」—— `reference/` `scorer/` `runs_in/` `gold/` `memory_probe_answers/` 的任何内容不进执行面那台机器。

**新口径（v1.0.16 起）**：**答案面永不挂进 agent 容器**；单机形态下答案面位于 `/task` 之外。判据是**挂载面 + run dir**，不是「机器上有没有」。

**为什么改**：本仓库公开发布时带全部答案面（用户裁定 N-627 走 B），否则外部用户跑完算不出分。答案面一旦在公网上，「哪台机器上有它」就不再有判别力。

**对公平性协议意味着什么** —— 这一条要说清，因为它是本文件的正题：
* **同期可比性不受影响**：所有臂在同一个容器边界下跑，看到的东西完全相同；
* **跨期可比性有风险**：题面与参考解在公网上，随时间推移可能进入模型训练语料，于是「今年的 80 分」与「去年的 80 分」不再等价。这是**设计性限制**，登记在 `ops/reports/known_limits_v1.md`，v1.1 以**留出集**（held-out split）处理 ——留出集不公开，只有它能支持跨期结论。
* **canary 与 memory_probe 的角色变了**：`memory_probe_answers/` **仍然不公开**（它是钥匙，公开即失效），canary 降级为「同期一致性检查」而不再是「记忆污染检测」。
