# 源B:qlib community instruments 的区间约定考据

卡 **1.1-sourceB**。代码 `snapshots/universe_qlib.py`,机器可读摘要 `ops/universe_source_B.json`,
产物 `$SNAPSHOTS/v1/universe/qlib_instruments_intervals.parquet`。

> **这份文档的存在理由**:源A(湖 `index_weight`)是**月末时点快照**,源B 是**区间**。
> 两边的区间约定不统一,对账结果就是垃圾。下面把源B 的约定钉死,并给出证据。

---

## 0. 结论(先给答案)

qlib instruments 的 `code<TAB>start<TAB>end` 是 **闭日历区间 `[in_date, out_date]`**。

| 问题 | 答案 |
| --- | --- |
| 闭区间还是半开? | **闭**。`in_date` 与 `out_date` 当天都算在内 |
| `in_date` 是什么 | **生效日**。当天该票**已经**在成分内。100% 落在交易日上 |
| `out_date` 是什么 | **最后一个仍在成分内的日历日**。**不是退出日** |
| 退出日怎么算 | `out_date + 1 天`(= 下一段/下一期的 `in_date`) |
| `out_date` 是交易日吗 | **不保证**。csi300 只有 68.5% 是,其余落在周日与节假日 |
| 折成某日名单怎么写 | `in_date <= D <= out_date` |
| 等价的半开写法 | `[in_date, next_in_date)` —— 按**日历天**推进,**不是** `[in_date, out_date)` |

**最容易踩的坑**:把它当成 `[in_date, out_date)`。那样写会在**每一个成分调整边界日**
把当天的成分整批丢掉 —— 实测在 2009-06-30 / 2010-06-30 / 2011-06-30 这三天,
csi300 的名单会从 300 只直接塌成 **0 只**(见 §3.3)。

## 2. 代码规范化

规则:**前 2 个字符是交易所前缀,其余是代码本体**,拼成 `<symbol>.<EX>`。

```
SH600000 → 600000.SH      SZ000001 → 000001.SZ      BJ430017 → 430017.BJ
```

前缀不是拍脑袋定的,是**全量扫出来的**:

| 前缀 | 出现次数(6 个文件合计 256 236 行) |
| --- | --- |
| SZ | 133 075 |
| SH | 121 620 |
| BJ | 1 541 |

**只出现这三种**;所有代码都是 8 字符。解析器对不认识的前缀走 `unmapped` 清单**上报**,
绝不静默丢弃 —— 本轮 `unmapped = 0`。

### 2.1 形态异常:`SHT00018`

csi300 里有 **7 行** `SHT00018`(2005-04-08 ~ 2007-01-03),代码本体 `T00018` 不是 6 位数字。
按前缀规则照常映射成 `T00018.SH` 并**保留在产物里**,同时打进 `symbol_anomalies` 上报。

它是一条**悬空成分**:

* 不在 `all.txt` 里
* 不在 qlib 发布的 `features/` 里(整个 `features/` 没有任何 `sht*` 目录)
* 不在湖 `stock_basic` 里

也就是**有成分记录、没有任何价格数据**。用 csi300 建 2005-2007 的宇宙时必须显式处理。
(登记为风险 **B-05**)

### 2.2 归一化成功 ≠ 在湖里查得到

前缀规则零失败,但归一化后的代码在湖 `stock_basic`(5 890 个 ts_code)里**查不到**的有:

| 宇宙 | 去重 code | 湖内查不到 | 分类 |
| --- | ---: | ---: | --- |
| all | 6 142 | 258 | 248 北交所旧码 + 6 指数 + 4 A 股 |
| csi300 | 949 | 2 | `000022.SZ`、`T00018.SH` |
| csi500 | 1 802 | 3 | `000022.SZ`、`000043.SZ`、`300114.SZ` |
| csi800 | 2 016 | 3 | 同上 |
| csi1000 | 2 803 | 4 | 同上 + `601313.SH` |
| csiall | 5 718 | 125 | 121 北交所旧码 + 4 A 股 |

那 4 个 A 股代码(`000022.SZ` / `000043.SZ` / `300114.SZ` / `601313.SH`)不是退市 ——
湖 `stock_basic` **保留**退市码(例:`600591.SH` `*ST上航(退)`,`delist_date=20100125` 在册),
却没有这 4 个,说明它们是**代码变更**注销的。对账时会表现为"源B 有、源A 没有",不要当成源A 漏数。

> 湖里能查到形近的接续码 `001872.SZ`(招商港口)、`001914.SZ`(招商积余)、`601360.SH`(三六零),
> 但**本卡没有证据链证明映射关系**,不写进产物,留给人工核对。

## 3. 区间约定的证据

### 3.1 结构证据一:`in_date` 全是交易日,`out_date` 不是

对照 qlib 发布自带的交易日历 `calendars/day.txt`(6 458 个交易日,2000-01-04 ~ 2026-08-26):

| 文件 | `in_date` 是交易日 | `out_date` 是交易日 |
| --- | ---: | ---: |
| csi300 | **100.0%** | 68.5% |
| csi500 | **100.0%** | 91.1% |
| csi800 | **100.0%** | 88.2% |
| csi1000 | **100.0%** | 84.8% |
| csiall | **100.0%** | 91.8% |
| all | **100.0%** | **100.0%** |

`in_date` 是生效日,自然落在交易日;`out_date` 大量落在**周日和节假日**
(实例:`2006-07-02` 周日、`2008-01-01` 元旦、`2025-06-29` 周日)。
一个"最后一个成分内**交易日**"是不可能落在周日的 —— 所以 `out_date` 是**日历减法**的产物。

### 3.2 结构证据二:星期分布可以逐项配平

csi300 的 `in_date` / `out_date` 星期直方图(0=周一 … 6=周日):

```
in_wd  = {周一 3300, 周二 3298, 周三 2400, 周四 1800, 周五 5400}          周六/周日 0
out_wd = {周一 3300, 周二 2400, 周三 2100, 周四 5100,           周日 3298}  周五/周六 0
```

如果 `out_date = 下一期 in_date − 1 日历天`,那么 `out_wd[k]` 应当等于 `in_wd[k+1]`,
差额只能来自**首期**(没有前驱 `out`)与**末期**(没有后继 `in`)。逐项核:

| 关系 | 期望 | 实测 | 差额来源 |
| --- | --- | --- | --- |
| `out(周三)` ← `in(周四)` | 1 800 | 2 100 | `+300` = 末期 `out=2026-08-26`(周三)的 300 只 |
| `out(周四)` ← `in(周五)` | 5 400 | 5 100 | `−300` = 首期 `in=2005-04-08`(周五)的 300 只 |
| `out(周二)` ← `in(周三)` | 2 400 | 2 400 | 0 |
| `out(周日)` ← `in(周一)` | 3 300 | 3 298 | `−2` = 298 人期 `in=2009-12-29`(周二)少 2 |
| `out(周一)` ← `in(周二)` | 3 298 | 3 300 | `+2` = 同一期,前驱 `out=2009-12-28`(周一)有 300 |

**五项全部配平,余数为 0。** 生成规则就是纯日历的 `next_in − 1 day`,
所以 `out_date` 是闭端点(闭区间右端 = 下一期开始的前一天)。

`out_date` **永不落在周五和周六** —— 因为那要求下一期的 `in_date` 落在周六/周日,
而 `in_date` 从不落在周末。这条否定性预测也成立。

### 3.3 外部证据:湖 `index_weight` 月末快照(判决性)

对每个快照日 `D`,分别用**闭**(`in<=D<=out`)与**半开**(`in<=D<out`)把 qlib 区间折成当日名单,
与湖里的名单比对称差:

| 宇宙 | 快照日数 | 闭:总对称差 | 半开:总对称差 | 闭:完全一致的快照日 |
| --- | ---: | ---: | ---: | ---: |
| csi300 (`000300.SH`) | 211 | **42** | 942 | 190 / 211 |
| csi500 (`000905.SH`) | 211 | **144** | 1 636 | 143 / 211 |

真正能区分开闭的,只有"快照日**恰好等于**某条 `out_date`"的那几天。csi300 有 3 天:

| 快照日 | 湖成分数 | 闭区间给出 | 对称差 | 半开区间给出 | 对称差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2009-06-30 | 300 | **300** | **0** | 0 | 300 |
| 2010-06-30 | 300 | **300** | **0** | 0 | 300 |
| 2011-06-30 | 300 | **300** | **0** | 0 | 300 |

csi500 在同样三天:闭区间 500/500(对称差 2/4/2),半开区间 **0**(对称差 500)。

**判决**:`out_date` 当天该票**仍在成分内**。闭区间。

> csi1000 没有任何快照日落在 `out_date` 上,这项对它无判别力(总对称差 7 513
> 主要来自 §4 的 B-01 缺口,不是约定问题)。

## 4. 三种文件的语义不同,禁止混用

| 文件 | 语义 | 行数 | 去重 code | 一 code 几段 |
| --- | --- | ---: | ---: | --- |
| `all.txt` | 每只票**一段**总的上市/有数据区间 | 6 142 | 6 142 | 恒为 1 |
| `csi300/500/800/1000.txt` | 成分区间,**多段** | 16 198 / 22 503 / 59 207 / 33 008 | 949 / 1 802 / 2 016 / 2 803 | 最多 54 / 45 / 86 / 33 |
| `csiall.txt` | 中证全指成分,**多段** | 119 178 | 5 718 | 最多 35 |

`all.txt` 只有 6 142 行而 csi300 有 16 198 行,**不是因为 all.txt 更小**,
而是因为两者根本不是一回事:前者一票一段,后者一票被上游快照期切成几十段。

### `all.txt` 的端点也不能当上市/退市日用

* 6 142 行里 **925 行**的 `in_date` 是日历起点 `2000-01-04` —— **左删失**,不是上市日。
* 5 552 行的 `out_date` 是发布日 `2026-08-26` —— **右删失**,不是退市日。
* `all.txt` 两端都是交易日(100%),这点与 `csi*` 不同。

### `all.txt` 里混着 6 个**指数**

`000300.SH`、`000852.SH`、`000905.SH`、`000906.SH`、`000985.SH`、`399300.SZ`
(原始码 `SH000300` / `SZ399300` …,区间都从 `2005-01-04` 起)。
当股票宇宙用之前**必须过滤**,否则凭空多出 6 只"票"。`csi*.txt` 里没有这个问题。
(登记为风险 **B-04**)

## 6. 产物与冻结线

### 字段

`$SNAPSHOTS/v1/universe/qlib_instruments_intervals.parquet`,**256 220 行**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 归一化代码 `600000.SH` |
| `universe` | string | `all` / `csi300` / `csi500` / `csi800` / `csi1000` / `csiall` |
| `in_date` | **date32** | 闭区间左端,生效日 |
| `out_date` | **date32** | 闭区间右端,最后一个仍在成分内的日历日 |
| `raw_code` | string | 原始 qlib 代码 `SH600000` |
| `source_file` | string | `csi300.txt` |

排序:`universe`(按 `UNIVERSE_ORDER`)→ `code` → `in_date`。
**日期是 `date32`,不是字符串** —— 区间表的核心操作是比大小,
字符串日期最容易在跨源对账时写成 `'20260731'` vs `'2026-07-31'` 的坑。

### 冻结线处理(红线 7)

| 动作 | 规则 | 影响 |
| --- | --- | --- |
| 丢行 | `in_date > 2026-07-31` 整行丢弃 | 仅 `all` 的 **16** 行(2026-08 新上市的北交所票) |
| 截断 | `out_date > 2026-07-31` 截到 `2026-07-31` | all 5 539 / csi300 300 / csi500 500 / csi800 800 / csi1000 1 000 / csiall 5 061 |

**原始文件里没有任何一行天然 `out_date == 2026-07-31`**(代码里重新核过并写进
`freeze.censoring_sentinel_is_unambiguous`),所以产物里:

```
out_date == 2026-07-31   ⟺   右删失(截至冻结线仍在成分内 / 仍有数据)
```

可以直接这么判,不需要额外的 flag 列。

## 7. 怎么用(给对账卡和下游)

**折成某一天的宇宙** —— 唯一正确写法:

```sql
SELECT code FROM intervals
WHERE universe = 'csi300' AND in_date <= DATE '2026-06-30' AND DATE '2026-06-30' <= out_date
```

**与源A(湖 `index_weight` 月末快照)对账**:

1. 源A 是时点快照,源B 是区间 —— 用上面的闭区间条件把源B 折到源A 的快照日再比。
2. 源A 的 `trade_date` 是 `'YYYYMMDD'` 字符串,源B 是 `date32`,**先统一类型**。
3. 源A 只有 `000300.SH / 000905.SH / 000852.SH` 三个指数,且从 `2009-01-23` 起 ——
   csi300 的 2005-2008、csi800、csiall **无源A 可对**。
4. 预期残差不为零:csi300 211 个快照日里 190 个完全一致,其余对称差 ≤ 2(1 只票的换手时点差)。
   **对称差突然变大只可能是约定用错了**,不是数据问题。
5. 先剔除 §5 的 B-01 / B-02 时段和 §4 的 6 个指数码,否则会被淹没在已知缺口里。
